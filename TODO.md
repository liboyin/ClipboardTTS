### NB11 — execution boundary

NB11a (D11) landed first: every engine start publishes through one owner in `AudioPlayerManager`, a failed start no longer invalidates the format, and a new session retries a stopped engine. README owns that contract. NB11b builds on that owner.

**NB11b — configuration-change recovery (D10).**
- **Intent:** after `AVAudioEngineConfigurationChange` the app is usable again without Settings and never shows playback that is not happening.
- **Dependencies:** NB11a; D10; [Apple engine configuration changes](https://developer.apple.com/documentation/avfaudio/avaudioengineconfigurationchangenotification).
- **Direction:** the player observes that notification for its own engine through an injected notification center and handles it on the main queue. Handling suspends playback the way Pause does, which revokes the current generation's pending automatic start and any underrun resume, even before the first PCM. It then restarts the engine through NB11a's owner and re-anchors the node at the published position without playing, because a restarted engine's schedule cannot be trusted. If the restart fails, `play()` restarts the engine and re-anchors before it plays. The handler does not cancel the request, advance a generation, or discard buffered PCM.
- **Non-goals:** no auto-resume on the new device; no reconnecting the graph for a new hardware format (Apple keeps connections); no macOS 13 or live-device automation.
- **Validation:** tests post a notification from an owned center with the test-owned engine as object, off the main thread. Cover: playing, prebuffer-pending, underrun-suspended, manually paused, and idle states; a failing restart then Play; a notification for another engine ignored; the observer removed with its owner. Mutants: no observer; resume instead of pause; no re-anchor; no automatic-start revocation; handling off the main queue; acting on another engine's notification. A physical-device smoke test (disconnect output during speech) is recorded as performed or as a limitation.
- **Done:** gates pass, review finds no Blocking issue, README describes the recovery policy, and NB11's entry is removed.

- **NB9 — Fixed.** A PCM format is applied through `SpeechSessionCoordinator.applyAudioFormat(sampleRate:)`, which cancels the request paired with the audio that change discards. Each manager still revokes its own half, as when a session is replaced: the owner cancels the request and `setSampleRate` clears the audio, so one change advances each generation once. The request is released before the graph is touched, matching the order `cancel()` uses. The order is load-bearing: rebuilding the graph takes long enough for the request to complete inside it, and a cancellation arriving after that would find nothing to cancel and leave the finished request publishing the failure of a session the format change had already retired. `AudioPlayerManager.changesAudioFormat(to:)` answers whether a rate replaces the active format, and `setSampleRate` decides with that same answer, so the prediction and the change cannot disagree. `TTSNetworkManager.stopActiveSpeechRequest()` decides and revokes in one visit to `stateQueue` under callback authority, because a request completing between a separate check and the revocation would be "cancelled" by advancing a generation it no longer owned. - **NB1 — Fixed.** A success response now has to say what it is before any of it is played. `SpeechResponseFormatPolicy` owns that decision for both provider paths and reads a declaration the same way for each: parameters dropped, case folded, and a value that is not one media type refused rather than parsed. Only an absent or blank header is silence; every other value is something the provider said and has to be a whole media type, its type and subtype both HTTP tokens. A header carrying several types, which is how URLSession presents a response that declared two, has not declared what its body is, and reading only as far as its first parameter would let its leading half excuse the rest. A value carrying only parameters, and a subtype such as `()` or an emoji, are refused for the same reason rather than read as silence: since the audio tree is accepted without inspecting the subtype, whether a value is a media type at all is the last thing standing between a provider-controlled header and the player, and an adversarial review found that gap open before this landed. An OpenAI-compatible or Custom body is judged by its `Content-Type` and the accepted set is deliberately open: nothing at all passes, because OpenAI's own reference documents no content type for `/v1/audio/speech`; any `audio/*` passes without inspecting the subtype, because which one a compatible server labels raw samples with is documented nowhere and narrowing it would refuse a working deployment on a guess rather than on evidence; `application/octet-stream` and `binary/octet-stream` pass as the generic spellings D4 names. Everything else is refused, which is what closes the finding: two bytes of JSON returned with HTTP 200 were being handed to the player, and bytes that are not samples are not silently unplayable but audibly wrong, since the player reads every one of them as a little-endian 16-bit sample and renders them as full-scale noise. The refused body is dropped the way a non-2xx body already is rather than cancelled, because cancelling would end the task with a URL error and give the request a second reason to fail that is the app's own doing; `TTSNetworkManager.unplayableResponseFormatFailure` then points at the endpoint instead of inviting a retry, since a request that succeeded and returned something other than audio is answering correctly for whatever is at that address, and it quotes neither the declaration it refused nor anything else the provider sent. It is reported after an HTTP status, which stays the more actionable cause, and before a transport error, which only says that a body the app had already decided to discard stopped arriving. Gemini takes none of that rule — `text/event-stream` is the correct declaration for its transport — and is judged instead on each part's own `mimeType`, where the accepted set can be exact because one fixed provider publishes what its speech output declares: `audio/L16`, as `audio/L16;codec=pcm;rate=24000`, and `audio/pcm`, the spelling Google's Live API uses for the same samples. A part declaring anything else is a malformed event on the existing fatal path, which is right for a blob type the schema documents as carrying images, video, PDFs, and text as well. A part declaring nothing is still decoded, because the request asks for the `AUDIO` response modality alone and refusing an undeclared part would trade a defect nothing has produced for the loss of every Gemini utterance if the field were ever omitted; a `mimeType` of another JSON type counts as undeclared for the reason a `finishReason` of another type does, while a readable declaration naming other media does not.
