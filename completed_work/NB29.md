# NB29 — The app targets macOS 14

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB29 — Fixed (D12).** `ClipboardTTSApp` now targets macOS 14, the same minimum as its test bundle, so every gate runs on the app's own floor and no macOS 13 claim remains to evidence. Raising the target made the single-argument `onChange(of:perform:)` deprecated, so the form's five observers use the macOS 14 zero- and two-argument forms with their default `initial: false`, which keeps them from firing on mount. Fifteen mutants were run against the full suite in an isolated scratch copy, against an unmutated control that passed. Nine each fail a named test: dropping the provider, endpoint, sample-rate, model, or voice callback, passing the sample-rate observer its old value, and firing the provider, sample-rate, or model observer on mount. The endpoint drop and the two mount-time mutants on the provider and sample-rate observers first survived; `SettingsChangeObservationTests` now covers an endpoint edit reaching future requests, one discovery per open, no invalid format published while the form mounts, and a fractional saved rate surviving a mount while speech plays, which a whole-number draft and a draft filled from the default rate each fail. A probe showed that the sample-rate observer firing on mount judges an empty draft before the saved rate replaces it. For the floor itself, `DeploymentTargetTests` reads both bundles' `LSMinimumSystemVersion` and fails a test floor of 15 alone or with the app's; an app floor of 15 alone, or of 13, fails the build instead. Each floor mutant was built from empty derived data. **Tooling note:** the first coverage run after the target change crashed every hosted Settings test in `SettingsView` value copies, from stale incremental products; the same suite passed from fresh DerivedData, and the gate passed after clearing the project's DerivedData.
