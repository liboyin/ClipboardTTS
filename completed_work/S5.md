# S5 — Replace asynchronous catalog publication with provider-local lookup

**Origin:** the full-project review of 2026-11-03 (TODO Evidence provenance) found that after D31 the manager's metadata path only read `ProviderMetadataCatalog`, yet kept request tokens, generations, abandonment, queued publication, a completion observer, and synthetic-completion test hooks. On 2026-11-15 the user invoked grouped task execution for the Simplification proposals and chose S5, S6, and S9. Choosing S5 accepted D38, which supersedes D19 and was recorded in `1345237` before implementation. S5 was committed last, after [S9](S9.md) and [S6](S6.md).

## Accepted boundary

The boundary was kept in the group's working review record.

- **Intent (D38):** `ModelVoiceConfigurationView` takes its picker choices from `ProviderMetadataCatalog.models(for:)` and `voices(for:)` for the provider its form renders, and no longer observes `TTSNetworkManager`. The catalog-only machinery is removed: `ProviderSuggestions`, the published suggestion lists, the metadata request tokens, generation, completion type and observer, the publication flag, list clearing, the two fetch methods, their DEBUG hooks, and `updateSettings`' metadata-scope invalidation. `SettingsView.syncSettings` loses its `refreshingLists` mode.
- **Retained behavior:** each form offers its own provider's choices, including on the render before `onChange` after a provider switch. An unknown saved model or voice is offered first and selected. Custom renders no picker, even for a Google-looking host. Catalog contents and order are unchanged. Typed and picker edits each run their callback once, and rebuilt choices run none. Opening Settings or switching provider does not rewrite a saved value or what a request sends. `updateSettings` still replaces the configuration whole.
- **Must not remove:** request generation, callback authority, request-state publication queueing, speech request snapshots, redirect policy, and `MockURLProtocolTestCase` isolation.
- **Compatibility surface:** Settings' visible choices, order, and selection are unchanged for every provider; persistence and provider-request contracts are unchanged; menu, Services, clipboard, and audio-session are untouched.
- **Non-goals:** NB60's accessibility names; S6's defaults; any new provider abstraction.
- **Validation and done:** a removed-behavior inventory comes first. Before old coverage goes, mutation shows that retained or new tests reject each protected regression; token-race tests whose mechanism is gone need no mutant. The gates pass, documentation is updated, and the change is reviewed and archived.

**Revalidation at `7d72ed0`:** both fetch methods only read the catalog; the token state lived at `TTSNetworkManager.swift:83`–`:87` and its invalidation at `:202`–`:216`; `SettingsView.swift:320` refreshed; `ModelVoiceConfigurationView.swift:7` observed the manager only for suggestions. D19's protection, refusing the previous provider's list on the render before `onChange`, is subsumed: a form that names its catalog by its own provider never holds another provider's list.

## Implementation

**S5 — Done.** The implementation agent from S6 (a Claude Code general-purpose subagent) was resumed for S5. A usage limit stopped it once, and it resumed with its work intact and no processes left running. Early on it ran `git rm --cached` on the deleted source, against its brief, and undid it at once with `git reset`; the main agent confirmed the index was clean and HEAD unchanged.

- **Removed:**
  - `Sources/Managers/TTSNetworkManager+Metadata.swift` is deleted; `check-coverage.sh` did not name it.
  - `TTSNetworkManager` loses the suggestion lists, the completion observer (property, init parameter, and doc), the metadata generation, identifier, tokens, and publication flag.
- **`TTSNetworkManager` changes:**
  - `updateSettings` only replaces the configuration under `stateQueue`.
  - `requestSettings` is now `private`, because its only outside reader was deleted.
  - The type's confinement rules no longer mention metadata.
- **`ModelVoiceConfigurationView`:** `pickerChoices(from: [String]?, selection:)` returns no choices for a provider with no catalog (`nil`), and otherwise puts an unknown selection first.
- **`SettingsView`:**
  - `syncSettings()` applies the form and the audio format.
  - `applyModelOrVoiceChange` is removed; the rows and key binding call `syncSettings` directly, the same work as before.
- **Docs and configuration:**
  - The catalog's and Settings' retry doc comments no longer describe publication.
  - `.swiftlint.yml`'s `nesting` comment now names the two remaining nested declarations. With `type_level: 1` layered onto the real configuration, SwiftLint 0.65.1 reported exactly those two (`TTSNetworkManager+Requests.swift:11`, `TTSNetworkManager+GeminiStreaming.swift:121`), so `type_level: 2` stays.
  - DESIGN's Source Layout, Network, Provider identity, Settings, Voice metadata, and Test Harness text describe the per-render lookup.
- **Tests:**
  - **Deleted:** `MetadataTestSupport.swift`, `MetadataTestSupportTests.swift`, and the four `TTSNetworkManagerMetadata*Tests.swift` files. `documentedGeminiTTSVoices` moved into `ProviderMetadataCatalogTests.swift`.
  - **Rewritten:** `SettingsVoiceMetadataTests` now has `testACustomFormOffersNoCatalogEvenForAGoogleLookingHost` and `testFieldsOfferTheCatalogsOfTheProviderTheyRender`. Its provider-switch test now also clicks Test Voice and checks that the request sends the saved `Sulafat`.
  - **Added:** `testAFormReRenderedWhileTheManagerHoldsAnotherProviderOffersItsOwnCatalogs`. It holds the form on Gemini while the test-owned manager is pointed at OpenAI, and forces a re-render through `isStreaming`.
  - **Reworked:** `SettingsMetadataRefreshTests` takes its values from the catalog. It rebuilds choices by prepending a typed value and by switching provider, and its last test is `testEachKeyModelAndVoiceEditReachesFutureRequests`.
  - **Smaller edits:** metadata counters are dropped from `SavedKeyReadRecoveryTests`; `SettingsChangeObservationTests.testOpeningSettingsPublishesEachListOnce` is removed; `MenuBarViewTests`' suggestion assertion is dropped (the test is renamed `testMenuShowsNoVoiceControlAndSendsNoRequestOnAppearance`); `SuggestionPickerTests` no longer needs a manager and becomes a plain `XCTestCase`; `HostedSettings` and `TestNetworkSupport` lose their manager and observer parameters.
