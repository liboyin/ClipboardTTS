# NB45 — README's exit 1 omits an unexpected runner exception

**Origin:** [NB41](NB41.md)'s limitations observed that an unexpected exception before the control ends `run-mutants.py` with a traceback and Python's exit 1, which README's exit codes do not describe. The gap review of the D22 sequence (`916f254..ee80eed`, Codex `gpt-6-astra`, 2026-09-29) raised it as a Non-blocking finding and reproduced it on both interpreters with a `load_spec` that raises `KeyError`. On 2026-09-29 the user asked for it to be executed at once, since it groups with no open task.

**Boundary:** document the existing outcome where exit codes are described, in README and the runner's module docstring. Changing the outcome, for example refusing unexpected exceptions with exit 2, was out of scope: NB41 deliberately keeps them propagating so that a runner bug surfaces rather than reading as a refusal, and a verifier case holds that. This is a documentation-only change, which AGENTS exempts from the application gates and formal review.

**Probe, 2026-09-29, at `e28d034`, Python 3.13.9, `LANG=C.UTF-8`.** A scratch copy of the verifier's in-process ownership case recorded each report as the runner wrote it:
- An exception raised by `load_spec`, before the control, wrote no `results.json`.
- An exception raised by `classify` after the control began, which then propagated, wrote `results.json` with `complete: false`, `exit: 1`, and the error "the runner raised an unexpected exception".

An uncaught Python exception exits 1 with a traceback. A first probe that read `results.json` after the case's own post-run claim found none, because that claim removes the previous `results.json`; recording the report at the moment of writing fixed that. The scratch copy was removed.

**Change:** README's exit-code sentence and the module docstring now say that exit 1 also means the runner raised an exception it does not expect, a bug it surfaces with a traceback rather than a refusal. README adds that `results.json` then exists only if the control had begun, and records an incomplete run with that error.

**Verification:** the diff touches only README and the docstring's third paragraph. `argparse` reads only the docstring's first paragraph. `./verify-mutation-runner.py` passed 139/139 on Python 3.13.9 and 3.9.6 after the edit.

**Limitations:** the exit status of an unexpected exception is Python's rather than the runner's own, so it cannot be told apart from an unjudged mutant by exit code alone. The traceback on stderr and, after the control, `results.json`'s error field identify it.
