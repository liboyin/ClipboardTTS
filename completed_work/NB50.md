# NB50 — Settings no longer reaches model discovery

**Origin:** recorded on 2026-11-02 with the OpenAI Realtime migration (`70ca8a9`). D27 gave OpenAI a fixed model catalog, and `SettingsView.syncSettings` never asked Custom to discover, so no production path reached `OpenAIModelDiscovery` or the discovery task bookkeeping in `TTSNetworkManager+Metadata`.

**Decision:** D31 (user, 2026-11-02) — remove the discovery layer rather than offer discovery to Custom endpoints.

**Boundary:** delete the layer and every behaviour that exists only for it, and give each behaviour that outlives it an explicit owner. Compatibility surface: Settings keeps the same suggestions for OpenAI and Gemini and still offers none for Custom, and a key edit no longer republishes catalogs. No metadata request leaves the app. The menu, Services, clipboard, persistence and audio contracts are unchanged. Non-goals: NB51, and narrowing the endpoint half of the metadata source identity.

**Fixed.** `OpenAIModelDiscovery`, its suite, and the `metadataResponse` fixture are deleted. `fetchAvailableModels(baseURL:selectedProvider:)` now mirrors `fetchAvailableVoices`: it publishes the provider's catalog through the token guard, or abandons the request for Custom, and takes no key. The metadata request records are now bare tokens, and task cancellation is gone. Settings refreshes its lists only on opening and on a provider switch (`syncSettings(refreshingLists:)`); a key edit and a recovered key read apply the form alone.

Behaviours retired with the layer:
- the bearer-key request to `/v1/models`;
- the discovery transport refusal;
- the `tts` identifier filter;
- silent decode and HTTP failures;
- task cancellation on replacement and scope change;
- the key-driven model refresh;
- mock-scope teardown waiting on a discovery completion.

Behaviours kept, with their owners:
- **The token guard** — stale and abandoned publications, provider-only and endpoint-only invalidation, re-entrant scope change, and separate model and voice slots. Its tests in the metadata suites now run on catalogs.
- **The redirect policy for a task that is not the active speech request.** That task is now a Realtime handshake, so the tests use an unstarted one built on the manager's own session.
- **Credential restoration from a task's own request.** Its test uses an unstarted, untracked data task.

README now states that a `wss` handshake redirect is always refused, because the origin rule recognizes only `http` and `https`.

**Removed tests (13), each protecting only a retired behaviour:**
- all 7 in `OpenAIModelDiscoveryTests`;
- `testScopeChangesCancelThePendingModelRequest` and `testRefreshingTheSameSourceCancelsTheModelRequestItReplaces` (task cancellation);
- `testEmptySuccessfulMetadataResponsesClearCurrentLists` (payload decoding);
- `testCleartextMetadataSourceCannotStartARequestOrPublishLists` and `testLoopbackMetadataSourceStillDiscoversModels` (discovery transport);
- `testClosingTheMockScopeWaitsForADiscoveryCompletionAlreadyInFlight` (a discovery completion).

**Validation:** macOS 26.7.1 arm64, Xcode 27B52. The baseline at `65777cb`, from clean DerivedData, passed `./check-coverage.sh` with 440 tests (Managers 97.85%, application logic 97.35%). The candidate, from clean DerivedData, passed 427 tests with 0 failures and no source warnings (Managers 97.90%, application logic 97.37%), and the Debug build with signing disabled succeeded.

**Mutation evidence:** `./run-mutants.py` with default deadlines, 11 suites selected, on `65777cb` plus the candidate (target digest `3a0462aa…`); the control passed. All 11 mutants were KILLED, each by a named test:
- Regressions:
  - Custom publishes an empty list;
  - Custom publishes Gemini's list;
  - the model and voice slots are shared;
  - a refusal is recorded on whatever request is active;
  - credentials are restored from the active request instead of the task's own;
  - a non-active task's redirect is followed unchecked.
- Reverts: the abandonment ignores its token; a scope change keeps the model token; a key edit refreshes the lists; a recovered key refreshes models.
- Over-restriction: a provider switch refreshes nothing.

The token, slot, scope and redirect mutants are also the removed-coverage evidence: each retained property still fails a retained test.

**Review:** an independent Codex CLI session (`gpt-6.1-sol`, medium effort, as set by the dispatch command) made a full first assessment of the uncommitted candidate on `65777cb`. Verdict: no blocking findings and no Non-blocking findings or Nits. The repository matched the freeze inventory afterwards.

**Limitations:** none beyond the general rule that a Custom endpoint's models are whatever the user types.

**Cleanup:** the gate logs, spec, results and review lived in the session scratchpad and were removed after transfer; this record keeps the essentials.
