# NB31 — Hosted startup builds managers on the unrouted production session

**Origin:** Non-blocking finding NB31, recorded from the startup inspection on 2026-09-24 at `2f1843a` that followed NB26: `AppStartupDependencies.make` built its manager with no session configuration in both branches, so the hosted test app's own graph, and the four graphs `AppStartupDependenciesTests` built, held sessions without mock routing. The hosted graph's `ServicesCoordinator` observes `NotificationCenter.default` and `streamTTS` does not refuse an empty key, so only convention kept a Services notification posted during a run from sending a request to `api.openai.com`. No request was observed. Selected on 2026-10-12 as the first task of a group with NB18, sharing the invariant that each test owns exactly the network/session dependencies it needs.

**Boundary (D21):** `TTSNetworkManager` always builds its session from `productionSessionConfiguration()`, and a caller may inject only a routing layer applied on top of it. Every manager a hosted-test graph returns fails every request locally, production startup applies no routing, and no test builds an unrouted session. Retire NB26's `.productionDefault`, `UnroutedSessionToken`, `productionDefaultSessionPolicy()`, `.provided`, and `.ephemeral` as a manager policy. Compatibility: provider-request contracts and production startup preserved; menu, Settings, Services, clipboard, persistence and audio-session contracts unchanged; only test seams and the hosted test app's own graph change. Non-goals: NB17, NB18, the Services notification center, refusing an empty key, the manager's `secretStore` default argument, `TestNetworkFactory.makeSession()`, and the NB5 policy itself. Shared group constraint: any request a new test issues targets a loopback literal, so that even a mutant removing routing sends nothing off the machine.

**Revalidation:** at `b3d3456`, startup still called `TTSNetworkManager(secretStore:defaults:)` with no configuration, and the factory still carried the cases NB26 introduced.

**Change:** `TTSNetworkManager.SessionRouting` carries only protocol classes and additional headers, and `sessionConfiguration(routing:)` applies it on top of `productionSessionConfiguration()`, so no caller can substitute or alter the cache, cookie or credential policy. The manager's `init(routing:…)` has no default, so every construction states its routing. `RefusingURLProtocol` claims every request and fails it with `URLError(.cannotLoadFromNetwork)` and a fixed description, performing no I/O; it must claim every request because installing protocol classes does not remove the system's own HTTP loader, which a loopback probe on macOS 26.7.1 confirmed on 2026-10-12. `AppStartupDependencies.make` always gives the hosted-test branch `.refusingEveryRequest`; only the production branch's routing is injectable, defaulting to the named `AppStartupDependencies.productionSessionRouting` (nil). Startup regressions pass a marked refusing routing to the production branch. `TestNetworkFactory.makeManager` layers MockURLProtocol routing (protocol class and test-identifier header), so every mock-routed manager now runs on the production policy rather than plain `.ephemeral`. README describes the routing layer, the hosted graph's refusal, and the factory.

Tests: `testHostedTestStartupManagersRefuseEveryRequestLocally` sends a request to `http://127.0.0.1:9` through both the automatic and the injected hosted graph's own session and asserts the refusal's code and description, asserts neither graph took the production branch's marked routing, and asserts that the session's first routed protocol is `RefusingURLProtocol` and claims the graph's configured endpoint, OpenAI's models URL, Gemini's API root, and a remote cleartext Custom URL, by inspecting `canInit` without sending anything. `testProductionStartupLayersNoRouting` reads the production choice. `SessionConfigurationRoutingTests` covers no routing (policy alone, system protocol list, no headers) and routing layered onto the policy. `testMockRoutedManagerSessionKeepsTheProductionPolicy` reads the NB5 policy from a mock-routed manager's own session and asserts its request reaches MockURLProtocol tagged with the owning test's identifier.
