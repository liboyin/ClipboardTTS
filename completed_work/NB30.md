# NB30 — Factory sessions are registered for teardown to invalidate

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB30 — Fixed.** A test now fails when a factory session is not registered with its test scope. At `9b5f9c3`, removing the manager's session registration passed all 390 tests, and so did removing `TestNetworkFactory.makeSession()`'s, so neither was protected; this change covers both. Removing the manager's report of its own invalidation, or teardown's `invalidateAndCancel`, already failed named `MenuBarDeferredClipboardActionTests` cases, because teardown cannot reach quiescence until every registered session reports invalidation. Registration was therefore the only unprotected step. `MockURLProtocol.isRegisteredWithCurrentTest(_:)` reads the scope's registrations under its condition, and `MockURLProtocolTests` asserts it right after `makeManager()` and after `makeSession()`, one test per path, with no waiting. The query has to live in `MockURLProtocolScope.swift`, the only file that can read the private registry, and it takes the file past SwiftLint's 400-line limit. The file therefore takes the rule-specific `file_length` exception with its rationale, as `AudioPlayerManager.swift` does. `MockURLProtocolTests.swift` also gained the `@testable import ClipboardTTSApp` that AGENTS requires, which reading a manager's session needs. Mutants were run in an isolated scratch copy against an unmutated control that passed, and each fails the test for its own path: removing either registration, and registering either session with another scope. The first candidate asserted both paths in one test, so a query answering whether any session was registered, paired with an unregistered `makeSession()` session, survived; split into two tests, that pair and its manager counterpart both fail. That query alone survives, and is equivalent in these tests: each test's scope holds only the session under test. An over-restriction does not apply, because the change adds an observation and narrows nothing a correct factory may do. **Limitation:** the unrouted manager behind `productionDefaultSessionPolicy()` is never returned, so its registration is covered only because it goes through the same `makeManager` line.
