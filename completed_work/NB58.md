# NB58 — Early network tests wait on elapsed time and assert weakly

**Origin:** the 2026-11-03 second full-project review. [NB17](NB17.md) replaced fixed waits in the audio and metadata suites but left network-only waits outside its boundary:

- `Tests/TTSNetworkManagerTests.swift` slept 0.5 s inside a request handler and asserted after fixed `asyncAfter` delays.
- `Tests/MockURLProtocolTests.swift` released work, or proved absence, by elapsed time.
- `testNetworkManagerHandlesAPIError` asserted only that `isStreaming` was false 0.5 s after a 401, which would also hold if the 401 were treated as success.
- `testNetworkManagerIgnoresDataAfterStop` proved absence by waiting 0.2 s.

## Accepted boundary

The user started grouped execution on 2026-11-14 without naming tasks. The main agent selected NB58 with [NB61](NB61.md), because both are tests that cannot fail for the behavior they are named for and neither needed a user decision. Each was committed separately, NB61 first. The boundary, as it stood in TODO:

- **Shared constraints:** tests only. No production code, menu, Settings, Services, clipboard, persistence, provider-request, or audio-session contract changes. Keep `MockURLProtocolTestCase`'s ownership and quiescence guarantees and add no elapsed-time wait. A test helper added for a wait has one responsibility and its own doc comment. **Non-goals:** other weak tests, `MockURLProtocol` itself, and the NB54/NB60 accessibility work.
- **Intent:** each named case waits on explicit completion and asserts the behavior it is named for, or is removed where a retained test already protects that property.
- **Cases:** `testNetworkManagerStopsStreaming`, `testNetworkManagerIgnoresDataAfterStop`, `testNetworkManagerHandlesAPIError`, `MockURLProtocolTests.testTearDownWaitsForAnInFlightHandlerBeforeReleasingTheTestScope`, and `testTearDownInvalidatesSessionsBeforeADeferredTaskCanStartLoading`.
- **Validation:** for each strengthened assertion, a mutant breaking its property fails it (revert, plausible regression, and over-restriction where applicable). Each removal names the retained test that kills the same mutant.
- **Done:** no elapsed-time wait or sleep remains in those cases, gates pass, mutants are killed by named tests, and NB58 is archived.

**Revalidation at `057b50f`:** every cited line was present. `testNetworkManagerHandlesAPIError` duplicated `TTSNetworkManagerFailureTests.testAuthenticationFailurePublishesActionableAPIKeyGuidance`, which awaits the terminal state and asserts the exact 401 copy.

**Amendment (user decision, 2026-11-14):** proving that teardown waits for an in-flight handler has no event to wait on. That case may therefore close its scope under a bounded deadline and assert that the close refused to finish. The deadline is permitted because the passing outcome does not depend on it; it only limits how long a broken teardown gets to finish wrongly. `MockURLProtocolRecoveryTests.swift:46` already uses the same pattern.

## Implementation

**NB58 — Fixed.** A Claude Code implementation agent wrote the first candidate in a separate git worktree based on `057b50f` and produced its mutation evidence. The main agent applied that diff unchanged; both file hashes matched the tested copies. It then made the review fixes below itself.

- **`testNetworkManagerStopsStreaming`:** the sleep and the delayed check are gone. On the main thread, `stopStreaming()` publishes `isStreaming` and cancels the task before it returns. The test asserts straight after the call that `isStreaming` is false, the captured task is `.canceling` or `.completed`, and `activeTaskForTesting` is nil, after asserting `isStreaming` and `.running` before the stop. The handler is held by a semaphore that a `defer` releases.
- **`testNetworkManagerIgnoresDataAfterStop`:** a barrier on an injected audio-delivery queue replaces the 0.2-s wait. An accepted chunk is queued there before the delegate call returns. The late chunk and its completion are now driven with the task that stop actually cancelled, rather than a task from another session.
- **`testNetworkManagerHandlesAPIError`:** removed. The retained authentication-failure test kills both 401 mutants.
- **In-flight handler test:** it now lives in `MockURLProtocolInFlightLoadTests: XCTestCase` in the same file and opens and closes its own scope, as `MockURLProtocolRecoveryTests` does.
  - It holds the handler and asserts that `endTest(identifier:timeout: 0.2)` does not quiesce.
  - A registered delivery owner records whether the handler had returned when the scope released it: `[]` before the handler is released, then `[true]` after `finishClosingScopeOrEndRun`.
  - A close that wrongly quiesces ends the run with `fatalError` (review round 1).
- **Deferred-task test:** the 0.1-s sleep is gone. After quiescence the test asserts that the task completed exactly once as `.cancelled`, then resumes it and asserts it is still `.completed`.
  - If cancellation did not happen, the test fails, invalidates its own session, and waits for the task's completion instead of resuming it (review round 1).
  - If that completion times out, the run ends with `fatalError` (review round 2).

**Assumptions:**
- "Instantly transition the state" in the stop test means synchronous publication on the main thread, which the current code does.
- The deferred-task test relies on URLSession delivering a never-resumed task's cancellation before session invalidation finishes. This was observed on this machine with Xcode 27.2 across 30 iterations; it is not documented behavior.

The protocol callbacks after the handler live inside `MockURLProtocol`, which the boundary excluded, so no independent join exists.
- **Round 2:** finding 2 resolved. Finding 1 remained Blocking: the fallback's completion timeout still returned into teardown. **Validated. Fixed** by ending the run when that completion times out, verified by the `deferred-fallback-never-completes` probe.
