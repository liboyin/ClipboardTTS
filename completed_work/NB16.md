# NB16 — The coverage gate covers all application logic

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB16 — Fixed (D7, D15, D16, D17).** Every Swift source the app compiles is now gated application logic, and what is excluded is named symbol by symbol rather than by directory, so moving a file cannot change whether it is measured. Two verdicts must both hold at 85%: `Sources/Managers/` keeps a floor of its own beside the new one over the whole gated population, because a single combined number would have let the high-coverage views absorb a Managers regression down to roughly 78% before it moved. On this candidate, frozen against `41090c2`, they read 98.65% and 97.80%. The declarative-body rationale that had exempted `Sources/Views/` is gone, reconciled with what the report actually measures: the views run at 93–100% under the hosted suite, and the logic that had fallen under `Other` — `APIKeyProvider.keychainAccount`, `BundleAboutMetadata`, `AboutAction`, `InMemorySecretStore`, the migration and startup services — is gated like everything else. Three platform adapters are excluded, 76 executable lines: `AppKitMenuAlertPresenter.presentAlert(title:message:)`, which activates the app and runs a modal `NSAlert`; `StandardAboutPanelPresenter.showAbout(applicationName:applicationVersion:)`, which orders AppKit's standard About panel; and `KeychainSecretStore`'s four members, which reach the developer's real Keychain. An exclusion matches by substring, so the closures the compiler emits inside a symbol are excluded with it, and both of its counts leave the ratio. Per-function records make that arithmetic exact: their sums were verified on 2026-09-20 to equal their file totals for all 26 measured files, with unique names. NB15's fail-closed properties carry over to the wider population and gained their own: an exclusion that matches nothing in the source it names, a source the report does not measure, an unreadable function record, two exclusions claiming one function, and a source carrying an exclusion whose function records do not sum to its own counts are each a refusal, as is a listed zero-executable-line source — `Sources/SettingsKeys.swift` is the only one — that gains lines or leaves the repository. `verify-coverage-gate.sh` became `verify-coverage-gate.py` in the same change, because its fixture builder was already Python inside a heredoc and its case table grew here; it drives the same real script end to end over forty-two synthetic reports and now separates stdout from stderr, so a refusal must reach stderr and print no verdict. Forty-three mutants were run in an isolated scratch copy against an unmutated control that passed, and each fails a named case: gating only `Sources/Managers/` again, dropping either verdict, counting the excluded lines in the ratio, subtracting them from the denominator alone, matching an excluded symbol by equality rather than substring, searching every source for it rather than the one it names, and reverting the stale-exclusion, function-list, unreadable-function, double-claim, gated-line, listed-source, unlisted-source or Managers-population guard; together with NB15's reverts and regressions over the wider population, and over-restrictions requiring every record to carry functions, requiring an excluded symbol to be wholly uncovered, and refusing a listed source the report happens to name. Two survived an early run and were investigated rather than dropped: no case had pinned that an excluded symbol's covered lines leave the numerator, now pinned by a case asserting `SecretStore.swift` reads 79.00% when its excluded symbols carry 16 covered of 47, and none had removed a listed source from disk. Applying the function-sum check to every source carrying function records, rather than only to the sources an exclusion names, survived until the second review pointed out that the boundary is itself a property: the gate never reads those records, so a source no exclusion names may carry records that account for nothing, and a case now says so. A fourth review found that the verifier forbade a verdict only in the refusals' stdout, so a gate printing one to stderr survived all its cases; both streams are now checked, and that mutant fails eleven of them. Its Non-blocking finding, fixed here by user decision, was that README described a zero-executable-line source as carrying no record at all, while the gate accepts either no record or one carrying no lines, as a case already pinned. A third review found no Blocking defect and one Non-blocking one, which the user chose to fix here: the threshold was compared in binary floating point with a 1e-9 fudge, so a crafted report whose true ratio was 84.9999999999999999% passed as 85.00%, and counts beyond floating point raised an uncaught error and exited 1 rather than refusing. Both counts now stay integers — the verdict compares `covered * 100` against `85 * executable`, and the displayed percentage is truncated rather than rounded — so a ratio below the threshold fails however close it is, one that reaches it passes, and no report is too large to judge. The second review also found that the smoke checks named flows that do not reach their adapters: `presentAlert` has one caller, the refusal of OpenAI clipboard text over 4,096 characters, and About is a Settings sidebar control rather than a menu item. README now names both. The first adversarial review of this change found two Blocking gaps, both reproduced in a probe. The subtraction trusted an excluded function's own line count: a report whose three exclusion-bearing sources each overstated one excluded symbol by five executable lines subtracted uncovered lines the files never carried and reported 84.49% where the true ratio was 84.00%, which at the boundary is the difference between a refusal and a pass. A source carrying an exclusion must now have its function records sum to its own two counts, which makes the remainder exactly the functions no exclusion claimed, and that retired the weaker guard which had only caught an impossible remainder. The review also found that the Keychain smoke check covered saving and reading but not `KeychainSecretStore.deleteSecret`, which clearing a key in Settings reaches through `SettingsSecretState.saveSecret`; the documented procedure now clears the key and relaunches as well. Both are now cases. **Outstanding (D17):** the three exclusions' end-to-end smoke checks — a menu speech failure showing the alert `MenuBarView` built, About showing the application's name and version, and an API key saved in Settings surviving a relaunch and, once cleared, staying gone, since clearing is what reaches the excluded `deleteSecret` — are documented in README and have not been run by the agent. Run them before relying on those exclusions. **Limitation:** shellcheck is still not installed on this machine, so `check-coverage.sh` was checked with `bash -n` only. README owns the current policy.
