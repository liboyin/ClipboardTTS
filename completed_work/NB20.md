# NB20 — Provider catalogs, model discovery, and one resolved request configuration

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB20 (resolved request configuration) — Fixed (D18).** The configuration future requests read is now one `RequestSettings` value under `stateQueue`, in place of the five mutable fields that held the same thing — `baseURL`, `apiKey`, `model`, `voice`, and `selectedMetadataProvider` — and `updateSettings` replaces it whole rather than field by field, so no request can be built from a half-applied edit and no field can be left behind by one. `TTSNetworkManager.RequestSettings.resolved(provider:apiKey:defaults:)` is the pure function that decides what a launch starts with: the initializer no longer switches over providers to read their stored defaults, and what each provider starts with can be stated without building a manager or a session. The key is passed in rather than read there, because migrating and reading a saved key is `APIKeyStartupState`'s decision and a second read is what that type exists to avoid. Only a Custom deployment's endpoint comes from storage; OpenAI's and Gemini's stay fixed in source. The metadata freshness check reads that one value in its own `stateQueue` transaction, which is why it stays readable inside the type rather than becoming private — a cross-file extension cannot see a `private` property, and both fields it replaced were already `private(set)` for the same reason. Nothing outside the type reads it: every other reader goes through `requestSettingsSnapshot()`, `currentModel()`, or `isCurrentProvider(_:)`, which take the lock. Fifteen mutants were run against eight suites in an isolated scratch copy, against an unmutated control that passed, and fourteen fail a named test: reading another provider's model and voice keys, ignoring the stored Custom endpoint, giving Gemini OpenAI's endpoint, taking OpenAI's endpoint from storage, dropping OpenAI's model or Gemini's voice fallback, inventing a Custom model default, reading the key from plaintext preferences instead of taking the supplied one, resolving the startup configuration for a fixed provider rather than the persisted one, replacing the configuration while keeping the previous voice, and comparing the metadata scope after the replacement rather than before it. Three of the fifteen survived those eight suites and were investigated rather than dropped: rerun against the whole suite, dropping the endpoint from the invalidation comparison fails `TTSNetworkManagerMetadataLifecycleTests.testScopeChangesCancelThePendingModelRequest`, and invalidating for every edit — the over-restriction — fails `SettingsVoiceMetadataTests.testTypedOffCatalogModelAndVoiceStaySelectedBesideTheDocumentedCatalog`. **Limitation:** the fifteenth, dropping the provider from that comparison, survives the whole suite at this revision, which reproduces NB25's inherited claim with current evidence rather than leaving it historical. The comparison itself is unchanged by this change, and NB25 later closed it. README owns the current behavior.

**NB20 (provider catalogs and discovery) — Fixed (D18, D19).** `ProviderMetadataCatalog` now states what each provider documents — OpenAI's two voice sets with the model rule that chooses between them, Gemini's thirty voices in the guide's order, and the one Gemini TTS model that needs no discovery request — and `OpenAIModelDiscovery` owns the other half of that contract: the models endpoint a speech endpoint implies, refused when its transport would expose the key it carries, and the payload whose `tts` identifiers are offered. Both are pure, so a drifted catalog, a derived endpoint, and a payload shape are now stated and checked without a manager, a session, or a main-queue turn, and each reads 100% under the gate. `TTSNetworkManager+Metadata` keeps what decides whether an answer may still be shown — the token guard, the credential, and the publication — and lost 54 lines and the nested response model with them. The `nesting` exception in `.swiftlint.yml` had named that model as its reason, and now names all three declarations that actually use it — the speech request body's coding keys, one Gemini event's audio classification, and the discovery response's own model — which a `type_level: 1` probe on 2026-09-21 reported as its only consumers. A provider that documents no catalog answers `nil` rather than an empty list, which is what leaves a Custom endpoint's suggestions `.unpublished` instead of publishing an empty catalog under its name. **Assumption recorded in the boundary:** the configured model is now read for every provider rather than only for OpenAI — one extra `stateQueue` read per settings refresh — because which catalogs depend on the model is the catalog's own contract rather than its caller's. No existing test changed, so the manager suites still own the wiring, which is what fails when the caller stops passing the configured model, publishes a list for a provider that documents none, or stops publishing a documented one. Sixteen mutants were run against six suites in an isolated scratch copy, against an unmutated control that passed, and each fails a named test. Reverts: returning the current OpenAI voices for the two legacy models, dropping a Gemini voice, answering `[]` where a provider documents no catalog, documenting models for every provider, making Gemini's models need discovery, asking the speech endpoint for the model list, skipping the discovery transport guard, offering every discovered model rather than the `tts` ones, and reading an unreadable payload as an empty catalog. Three more revert the caller's wiring: passing a constant model instead of the configured one, publishing an empty list where the catalog says none, and dropping the documented-models branch. Over-restrictions: treating every `tts`-prefixed model as legacy, folding case before the legacy match, reading an empty catalog as unreadable, and refusing an endpoint that names no `/audio/speech` path. The pure suites kill the contract mutants and the manager suites kill the three wiring ones; two of the caller mutants are killed by `TTSNetworkManagerMetadataProviderTests.testVoiceCatalogsReflectProviderAndModelCapabilities` alone, which is why that suite's provider arms were left in place rather than replaced by the pure assertions. Re-verifying either provider's documented set against its guide is a provider-contract change and was not performed here. README owns the current ownership split.
