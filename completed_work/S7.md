# S7 — Collapse the HTTP completion snapshot

**Origin:** simplification proposal from the second full-project review of 2026-11-03 (TODO's Evidence provenance). `TaskCompletionResult` copied ten fields of `ActiveRequestContext` and built an inert client for the stale case; `userFacingFailure` had separate Gemini and Custom no-complete-frame branches although, since D26, an HTTP completion is only ever Gemini or Custom; `FailedGeminiRevocation.task` handed its caller back its own argument; and the provider-neutral `enqueueAudioDelivery` and `enqueueStreamTermination`, which Realtime and Custom also use, lived in the Gemini file.

## Accepted boundary

The user started grouped execution on 2026-11-14 with "choose tasks from Simplification proposals". The main agent selected S7 with S8, because both concern the 16-bit PCM frame rule: S7 merges the completion's frame-check branches, and S8 gives that rule one named owner. They were committed separately, S7 first. S5 (needs a decision superseding D19), S10 (needs a decision on tooling robustness), S9 (independent of this invariant), and S11 (documentation-only) were not selected.

- **Intent:** remove copy-only scaffolding from HTTP task completion without changing behavior.
- **Direction:** `processCompletedTask` returns `nil` for a stale completion, otherwise the context snapshot and its retry, both decided under `stateQueue` as before; one frame rule after Gemini truncation; drop the echoed task; move the two delivery helpers unchanged beside the request lifecycle; update DESIGN's file map.
- **Compatibility surface:** menu, Settings, Services, clipboard, and persistence contracts are untouched. Provider-request contracts are preserved: failure ordering and copy, the single bounded Gemini HTTP 500 retry and its ownership window, when `activeRequest` is cleared, generation-authorized delivery, and the callback-authority-before-`stateQueue` lock order. No audio-session contract is involved.
- **Non-goals:** no change to Realtime completion, to the delivery helpers' bodies, or to retry eligibility; no new type beyond what the collapse needs.
- **Validation and done:** the existing suites pass unchanged, the mutants below are killed by named tests, the gates pass, and the change is reviewed and archived.

**Revalidation at `85f30fa`:** every cited structure was present (line numbers as in TODO's entry). `ActiveRequestContext` and `GeminiSSEEventParser` are structs, so a copied context is an immutable snapshot taken under `stateQueue`; a Realtime context has no task identifier, so no task completion can match one.

## Implementation

**S7 — Done.** A fresh implementation agent made the change; the main agent reviewed the diff and integrated it.

- `TTSNetworkManager+Failures.swift`: `TaskCompletionResult` is gone. `processCompletedTask` returns `(context: ActiveRequestContext, retryAttempt: RetryAttempt?)?`, `nil` when stale, with the same guard, retry decision, and ownership-release condition. The completion delegate takes the snapshot; its local request generation is no longer optional, since a current completion always had one. `userFacingFailure(for:error:)` reads the snapshot, every branch keeps its order and text, and the two frame branches are one provider-independent rule placed after Gemini truncation.
- `TTSNetworkManager+GeminiStreaming.swift`: `FailedGeminiRevocation` no longer carries the task; `didReceive` cancels the `failedGeminiTask` it already holds, which is the same object.
- `TTSNetworkManager+RequestLifecycle.swift`: holds `enqueueAudioDelivery` and `enqueueStreamTermination`, byte-for-byte as before; its header mentions the delivery it queues.
- `DESIGN.md`: the file map now assigns guarded PCM and terminal delivery to RequestLifecycle, and Gemini SSE parsing and HTTP response chunks to GeminiStreaming.

No test changed.

## Limitations

- `e-failed-gemini-task-not-cancelled` survives. `MockURLProtocol.stopLoading()` is empty, and revocation clears the request so the task's later completion is stale either way, so no test can observe that a malformed Gemini stream's task is cancelled. The gap predates S7, which cancels the same object at the same point; closing it needs a test-harness change outside this boundary. The user accepted this gap without change on 2026-11-15.
- No live provider, Thread Sanitizer, or launch of the real app ran.
