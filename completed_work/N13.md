# N13 — Custom falls back to OpenAI's speech endpoint

**Origin:** the 2026-11-03 second full-project review, at `23a8871`. Until a Custom endpoint was typed, Custom requests went to `https://api.openai.com/v1/audio/speech` (`Sources/Managers/TTSNetworkManager+RequestSettings.swift`) and the Settings form showed that address (`Sources/Views/SettingsView.swift`), so the Custom key was sent to OpenAI. The fallback predated D26, after which OpenAI speech no longer uses that endpoint, while the Custom deployments README documents are local Kokoro servers.

**Decision:** D34 (2026-11-03): Custom's default endpoint is the native Kokoro server on the Apple GPU, `127.0.0.1:8881`, replacing the OpenAI speech fallback. The app posts to the Base URL as written, so the default is the full speech URL README gives for that server, `http://127.0.0.1:8881/v1/audio/speech`; plain HTTP is permitted because the transport policy allows loopback literals.

**Accepted boundary:** intent: a Custom provider with no saved Base URL uses that URL both at startup (`TTSNetworkManager.RequestSettings.resolved`) and in the Settings form (`SettingsView.Fallback.apiBaseURL`). S6 had not landed, so both copies changed together. Compatibility surface: the Custom form's displayed Base URL changes only when nothing is saved; the `SettingsKeys.apiBaseURL` key and every saved value are preserved and nothing is written at launch; Custom requests with no saved URL now go to loopback, so the Custom key stays on the Mac by default; OpenAI and Gemini endpoints, menu, Services, clipboard, and audio session are unaffected. Non-goals: S6's shared defaults, rewriting a saved URL (a saved OpenAI address stays as saved), NB61's test, Docker's 8880 instructions, and Custom's empty model and voice defaults. Validation: fresh-startup and hosted fresh-form tests state the exact value, saved-endpoint tests stay green, and mutants cover revert, plausible regression, and over-restriction for both copies. Done when both copies, tests, and README's Kokoro section are updated and gates, mutation evidence, and review pass.

**Revalidation at `48f7a98`:** both fallback copies still named the OpenAI speech URL, `EndpointTransportPolicy` accepted plain HTTP to loopback literals, and `kokoro/start-native.sh` binds `127.0.0.1` on port 8881 by default. DESIGN's OpenAI input-limit bullet also said Custom's default base URL was the retired OpenAI speech endpoint, so it was added to the documentation change.

**N13 — Fixed (D34).** `TTSNetworkManager+RequestSettings.swift` replaces the private `openAISpeechEndpoint` with `nativeKokoroSpeechEndpoint` and updates the `resolved` documentation; `SettingsView.Fallback.apiBaseURL` names the same URL. `RequestSettingsResolutionTests.testAFirstLaunchFallsBackToWorkingFixedProviderDefaultsAndAnEmptyCustomConfiguration` states the new value, and the new hosted `SettingsViewTests.testAFreshCustomFormShowsAndRequestsTheNativeKokoroEndpoint` checks that a fresh Custom form shows it and that the manager's request settings carry it. README's native Kokoro section says the URL is Custom's default Base URL until another is typed; DESIGN's input-limit bullet names the new default.
