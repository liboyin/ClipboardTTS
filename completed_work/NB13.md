# NB13 — Retry Reading Saved Keys

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB13 — Fixed.** Settings offers **Retry Reading Saved Keys** while any saved key could not be read — a separate control, with no automatic re-read, by user decision on 2026-09-18. `SettingsSecretState.retryUnreadableSecrets` rereads only providers still unreadable, so a key the user stored since is never replaced, and it adopts each key it can now read, counting "no key saved" as a successful read. It uses the path a secured migration already uses, so only that provider's read guidance gives way to the next unresolved one and an unfixed save failure stays. The form then hands the credentials to future requests and, when the selected provider's key changed, rediscovers models without republishing voices. The manager withdraws its startup read-failure message for a recovered provider only while that exact message is still shown. Both recovery controls moved into `SavedKeyRecoveryView` because `SettingsView.swift` was at the 400-line `file_length` limit; the migration section is unchanged. Out of scope: typing a key does not clear the menu's startup read failure, which the next speech request or stop clears. Sixteen mutants were run in an isolated scratch copy against an unmutated control that passed, and each fails a named test in `SavedKeyReadRecoveryTests`: a no-op retry, never or always rendering the button, dropping the credential handoff or the withdrawal, treating an absent key as a failure, rereading every provider, retrying only the first, withdrawing unconditionally or any provider's read failure, clearing all guidance on recovery, keeping a recovered provider unreadable, reporting a still-failing one as recovered, and never, always, or fully resyncing instead of rediscovering. The withdrawal's off-main dispatch branch is uncovered, as its migration sibling's already was, because Settings calls it on the main thread. README owns the current behavior.
