# S8 — Remove AudioPlayerManager's duplicated graph setup

**Origin:** simplification proposal from the second full-project review of 2026-11-03 (TODO's Evidence provenance). `setupEngine` and `setSampleRate` each built the format, connected `playerNode` → `timePitch` → main mixer, and stored `audioFormat`, and their failure paths disagreed: `setupEngine` set `formatError` but left `hasValidSampleRateConfiguration` true. The 2-byte frame size was a local literal in `scheduleAudio` and `seek` and a separate rule in `TTSNetworkManager.containsCompletePCMFrame`. `pcmData.unprocessed` never held more than one carried byte, and `isNodePlaying` was production API that nothing in the app read.

## Accepted boundary

Selected with [S7](S7.md) in the grouped execution the user started on 2026-11-14 ("choose tasks from Simplification proposals"); S7's record gives the selection rationale. S8 was committed after S7, on S7's commit `195ca12`.

- **Intent:** one owner for wiring the audio graph and one for the PCM frame size, without changing reachable behavior.
- **Direction:** one helper wires the graph for a rate and reports failure identically on both paths; one named constant gives the frame size to the player and the network frame rule; `pcmData.unprocessed` becomes a single carried byte only if that reads more simply; `isNodePlaying` moves under `#if DEBUG`.
- **Compatibility surface:** menu, Settings, Services, clipboard, persistence, and provider-request contracts are untouched. Audio-session contracts are preserved: the 0.1-second prebuffer, exact-end seek/replay, clamping, underrun release, D2 and D10 behavior, engine-start error handling, published state, and queue confinement.
- **Non-goals:** no change to `seek`'s algorithm or cost (NB55); no new seam solely to reach the unified failure branch.
- **Validation and done:** existing suites pass unchanged, a Release build shows `#if DEBUG` does not break production, the mutants below are judged by named tests, the gates pass, and the change is reviewed and archived.

**Revalidation at `85f30fa` and `195ca12`:** every cited structure was present; line numbers had shifted (TODO cited `:163`, `:181`, `:261`, `:375`, `:513`). `isNodePlaying` was referenced only by tests.

## Implementation

**S8 — Done.** A fresh implementation agent made the source change; a usage limit interrupted it once, and it was resumed with its context and reran every gate afterwards. The main agent reviewed the diff and added one test.

- `AudioPlayerManager.bytesPerPCMFrame = MemoryLayout<Int16>.size` replaces the two local literals in `scheduleAudio` and `seek`; `containsCompletePCMFrame` compares against it. It lives on the player, which owns the mono Int16 format and its decoding; a static constant adds no runtime coupling.
- `connectGraph(sampleRate:)` chooses the format, connects the graph, stores `audioFormat` on `bufferQueue`, and publishes `sampleRate`, `hasValidSampleRateConfiguration = true`, and `formatError = nil`, in the order the rate-change path used. On a format failure it publishes the configuration as unusable with the unconfigurable-rate message on both paths. `setupEngine` attaches the nodes, calls it, and starts the engine only on success; `setSampleRate` keeps its stop/disconnect preamble and return values.
- `isNodePlaying` is compiled only in Debug, where tests read it.
- `pcmData.unprocessed` stays `Data`: a carried `UInt8?` would need more code to re-join each chunk before slicing, and its one-byte bound already follows from the frame-aligned `removeFirst`.
- **Reachable-behavior differences:** none. At init, the success path now also writes the default `true`/`nil` and publishes `sampleRate` after connecting rather than before; nothing observes the player during init. The init failure branch now also sets `hasValidSampleRateConfiguration = false`, which is the unification asked for, and is unreachable: `AVAudioFormat(standardFormatWithSampleRate:channels: 1)` returned non-nil for all 80,001 half-hertz rates from 8,000 to 48,000 Hz and for edge and fractional values.
- **Added test (main agent):** mutants removing the success path's `formatError` and readiness resets survived, at the candidate and at HEAD, because no test applied an unsupported rate followed by a different supported one. Since S8 makes `connectGraph` their single owner, `AudioPlayerManagerTests.testValidRateAfterAnInvalidOneRebuildsTheGraphAndClearsTheFormatFailure` now does that and checks the result, rate, readiness, and error. No existing test changed. DESIGN names none of the changed symbols and needed no change.

## Limitations

- c3 is unjudged; a production build with that regression would crash the same way at launch.
