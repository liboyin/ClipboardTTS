# NB34 — A test that crashes, exits, or exceeds its allowance is killed by that test

**Origin:** reported by [S2](S2.md)'s second review on 2026-09-25 from real Xcode 27.0 runs, and recorded in TODO as not independently validated: `fatalError` or `exit` inside a test, and a test exceeding its execution allowance, each ended in `** TEST FAILED **` with no `error: -[…]` line, so `classify` returned `FAILED-UNNAMED` and the run exited 0, although Xcode printed `Failing tests:` naming the test. [NB35](NB35.md) reproduced the timeout case on 2026-09-26 and kept Xcode's test timeouts off, leaving the reading to NB34. The user decided the reading on 2026-09-27 (D23) and authorized it as the fifth task of the mutation runner's sequence (D22), after [NB41](NB41.md).

**Boundary (D23):** a failed run's named failures include the tests Xcode's own `Failing tests:` summary lists, so a test that crashes, exits, or exceeds an enabled execution allowance reads as `KILLED` by that test; `FAILED-UNNAMED` remains only for a finished failure that names no test, and it leaves the mutant unjudged (exit 1). The summary is read only from a failed run and only as the run itself prints it, its names merge with those of `error: -[…]` lines, and a `BUILD-FAILED` run stays one. `classify`'s and the module's docstrings and README's verdict, exit-code, `results.json`, and test-timeout text follow. Enabling Xcode's test timeouts in the runner or scheme, NB43, S4, any other verdict or exit-code change, and the exit status of an unexpected exception before the control were out of scope. Validation was verdicts over real logs, verifier cases on both interpreters, mutation evidence against the unmodified verifier, a real-Xcode campaign, AGENTS' gates, and the review skill's full procedure.

The crashed test's `Test Case '-[ClipboardTTSAppTests.ProbeTests testFatalError]' started.` line precedes the crash, and every summarized test in the probes had such a line. A test can print the summary's exact text, but only while tests run, before `xcodebuild`'s closing lines; a lint failure's block has the heading `Testing failed:`. D23's premise therefore held: the summary names the crashed, exited, and timed-out tests, and the run's own summary is the block directly above the final marker.

**Change.** `run-mutants.py`: `classify` unions the names of `error: -[…]` lines with `summarized_failures(log, preceding)`, where `preceding` is the log's lines above its final marker, and still reads names only when that marker is `** TEST FAILED **`. `summarized_failures` skips blank lines up from the marker, collects the lines matching a tab and `Suite.test()` (`SUMMARY_ENTRY`), and counts them only if the line above them is `Failing tests:` (`SUMMARY_HEADING`). Each test takes the module of its own `Test Case '-[Module.Suite test]' started.` line, so it reads `Module.Suite test` as an error line spells it and the two sources merge into one sorted set; a summarized test that no start line names keeps the summary's `Suite test`. The build-failure check still follows the named failures. `main` counts `FAILED-UNNAMED` as unjudged beside `NO-VERDICT` and `NO-TESTS`, so the campaign continues past it and exits 1. The module docstring's exit codes and `results.json` contents, `classify`'s docstring, and README's verdict paragraph, exit codes, `results.json` contents, and test-timeout sentence were updated; README no longer says that an enabled Xcode timeout would read as `FAILED-UNNAMED`. Nothing changed in `results.json`'s format: it already records every finished mutant's result, now described as including an unjudged one.

**Verifier.** Fourteen classification cases and one end-to-end case were added, and one end-to-end case changed; the stand-in test tool gains `SUMMARIZED`, a crash only the summary names. Helpers rebuild the real logs' shapes with shortened paths: a start line, `RESTARTED` (the restart line and a passing test), `CLOSING` (`xcodebuild`'s closing lines), and `failed_run`, which appends the summary, the marker, and `Testing started`.

- Real shapes: the `fatalError`, `exit`, and timeout logs are `KILLED` by their test; the assertion log names its test once; the several-suites log names all five failing tests and not the printed ones; the printing test in a passing run is `SURVIVED`; the class-level `setUp` crash is `FAILED-UNNAMED`; the lint log stays `BUILD-FAILED`.
- Anchoring: a summary a test printed in a failed run that has none of its own, and one printed above a marker the test also printed, are `FAILED-UNNAMED`; a summary-shaped block directly above a success marker is `SURVIVED`; summary lines without the heading are no summary.
- Naming: a summarized test takes the module of its own start line, not the first start line's or another test's in the same suite; one with no start line keeps `Suite test`.
- `every_judged_verdict_exits_zero` runs a kill, a survivor, a build failure, and a `SUMMARIZED` mutant, and requires exit 0, `BUILD-FAILED`, and `KILLED ClipboardTTSAppTests.ASuite testCrashes`. It previously ran a `CRASH` mutant and required `FAILED-UNNAMED` with exit 0, which D23 reverses.
- `a_failure_that_names_no_test_is_unjudged` runs a `CRASH` mutant and a later kill, and requires exit 1, stdout of exactly the control's, `crash: FAILED-UNNAMED`, and the later kill's lines, empty stderr, all three runs made, a complete report with exit 1, no error, and both results, and the copy restored.

The replaced assertions protected three properties, each still held. A build failure is a verdict that exits 0: `every_judged_verdict_exits_zero` still requires it, and counting `BUILD-FAILED` as unjudged fails it. A finished failure that names no test is reported as `FAILED-UNNAMED`: the new end-to-end case and six classification cases require it, and reporting it as `NO-VERDICT` fails all seven. The campaign continues past it: the new case requires the later mutant's run and verdict, and stopping the run there fails it. `a_control_that_fails_without_naming_a_test_refuses` is unchanged, so a `FAILED-UNNAMED` control still refuses the run. `./verify-mutation-runner.py` passes 132/132 on Python 3.13.9 and on `/usr/bin/python3` 3.9.6; `HEAD`'s runner fails eight of the new or changed cases (124/132 counting the others): the six that need the summary read, `every_judged_verdict_exits_zero`, and `a_failure_that_names_no_test_is_unjudged`.

**Assumptions.** A summarized test that no start line names is reported as the summary's `Suite test` rather than dropped or left unjudged, since the summary still names it; no real log produced one. Several start lines naming the same suite and test in different modules would each be reported; this project has one test bundle.

**Limitations.** The reading is tied to Xcode 27.0's layout. If a later Xcode changes the heading, the indentation, or the summary's position above the marker, a crash reads as `FAILED-UNNAMED` again, which is now unjudged with exit 1, not a false verdict. The probes ran one test bundle, XCTest only, without parallel testing, and with top-level test classes; a nested class's summary spelling and a Swift Testing test's were not observed. The timeout reading was shown on the real probe log and in the verifier, not in a runner campaign, because the runner leaves Xcode's timeouts off. The spoofing defence relies on no test output appearing after `xcodebuild`'s closing lines, which every probe showed. The verifier stays locale-dependent (NB43) and was run under `C.UTF-8`. The crash probes and campaign left 13 macOS crash reports for the scratch builds' `ClipboardTTSApp`, which were removed afterwards.
