# S4 — Mutation verifier cases are independently runnable

**Origin:** a design proposal recorded on 2026-09-26 after [S2](S2.md)'s architecture discussion, with its structure validated by source inspection at `8c80839`: `verify-mutation-runner.py` nested its integration cases inside `end_to_end_cases`, and its entry point ran every classification, selector, and integration case with no way to select them. The user authorized it on 2026-09-27 (D22) as the last task of the mutation runner's sequence, after [NB34](NB34.md), so that its names cover the cases [S3](S3.md), [NB39](NB39.md), [NB40](NB40.md), [NB41](NB41.md), and NB34 added.

**Boundary:** every verifier case gets a stable name, under which its failure is reported. Naming cases runs only those, an unknown name fails explicitly, and a run with no name still runs the complete suite. Failures keep named attribution and a nonzero exit, and each case's scratch and processes stay owned when it fails. README documents the selection.

Out of scope:
- any change to `run-mutants.py`, its verdicts, or its exit codes;
- NB43, so the verifier was run under `C.UTF-8`;
- removing or weakening an existing case;
- a generic test framework.

Validation was the verifier on both interpreters, mutation evidence for the new invariants, the accumulated runner mutants rerun against the old and new verifiers, AGENTS' gates, and the review skill's full procedure.

**Revalidation** at `d9df5d5` on 2026-09-28, with NB34's recorded runner (`0cae08c1…`) and verifier (`0ed403cc…`). The 88 integration cases were closures inside `end_to_end_cases`, listed a second time in its `checks` tuple. `main` took no arguments, so `./verify-mutation-runner.py verdicts_and_restore --list` ran all 132 cases (132/132, exit 0) on Python 3.13.9. The four other closures, `case`, `gone`, `all_gone`, and `interrupted_by_a_terminal_during_generation`, were helpers, and every other closure was listed exactly once. A failure was reported as `classify: <description>`, `selectors: <description>`, or the integration case's function name, and none of these could be passed back to select that case.

**Change.** `verify-mutation-runner.py` keeps one ordered table, `CASES`, of `(name, check)` pairs.

- **Names.** A classification or selector case is named for its group and description: `classify/` or `selectors/`, then the description lowercased, with each run of characters other than letters and digits replaced by `_`. An example is `classify/a_passing_run_survives`. Each integration case keeps its function's name.
- **Integration cases.** Each moved from `end_to_end_cases` to module level with only its indentation changed, and is registered by the `@case` decorator in definition order. That order differs from the old `checks` tuple; no case depends on another's.
- **Runner loading.** `load_runner` is cached, so the table cases share one load of the runner.
- **Per-case wrapper.** `run_case` is the old wrapper: it gives each case its own temporary directory, and reports a crash or a failed cleanup as that case's failure.
- **Entry point.** `main(argv, cases)` takes case names and runs the selected cases in the suite's order, printing `FAIL <name>: …` for each failure and `passed/total`. It exits 1 on any failure. Before any case runs, it refuses with exit 2:
  - an unknown name;
  - a run with no name whose selection differs from the whole table (added after review round 2);
  - a selection of no case;
  - running cases under Python's optimization (`-O` or `PYTHONOPTIMIZE`), which removes the assertions every case checks with (added after review round 3).
- **Listing.** `--list` prints the names a run would take without running them, and it is still allowed under optimization.
- **New cases.** Seven cases hold the entry point, six of them over stand-in cases through `main`'s `cases` parameter:
  - a named selection runs only those cases, in the suite's order, accepting several names, a repeated name, and a name with a group;
  - an unknown name, or a name that is only a prefix, is refused with no case run;
  - no name runs every case, and an empty table is refused;
  - failing and crashing cases are each reported under their name while the rest run, and the run exits 1; every case's directory is its own and is removed, a failing case's included;
  - `--list` prints without running;
  - an optimized run is refused, under `PYTHONOPTIMIZE=1` and under `-O` in a child interpreter, while `--list` still works;
  - every real case's name is distinct, is one plain argument, and selects that case alone.

README's verification paragraph and the module and `main` docstrings describe the names, `--list`, the selection, and the refusals. `run-mutants.py` is unchanged. The default run now counts 139 cases: the 132 existing ones, all still run, and the seven new ones.

**Direct tests considered.** Exercising `load_spec` and `plan_edits` directly was considered and not added. Per-case timing on Python 3.13.9 put the ten integration cases that reach them at 4.3 s of a 90 s suite, and each can now be run alone. Each also holds wiring that a direct test would not: exit 2, the diagnostic, no traceback, and no test run. No integration assertion was replaced or removed, so AGENTS' coverage-removal rule was not engaged.

Every unmutated file's hash was unchanged. Only OWN-01, whose mutation is to leave directories behind, left any.

**Main-agent validation.**

- **Round 2's finding was Validated.** The main agent had already reproduced DEF-04 on both interpreters (44/44, exit 0, while `no_name_runs_every_case` fails when named). It validated the remedy's premise: a check that compares the no-name selection with the whole table sits outside the selection expression, so a fault in that expression cannot disable it. After the fix, DEF-01 to DEF-04 are refused with exit 2 on both interpreters, and CHK-02 to CHK-04 show the check is what stops DEF-04.
- **Round 3's finding was Validated**, on both interpreters, as reported.
  - The main agent also found the gap wider than the table cases. Under `PYTHONOPTIMIZE=1`, `HEAD`'s own verifier passed NB39-1 at 132/132 with exit 0, a mutant it fails by name at 131/132 without optimization, because its 88 integration cases already checked with `assert`.
  - Restoring explicit comparisons only in the 44 table cases would have closed S4's regression but left the finding's impact: an optimized run certifying a broken runner.
  - So the verifier refuses to run cases under optimization instead. That protects every case, keeps the file's one `assert` style, and stays in the entry point S4 owns. It is held by `an_optimized_run_is_refused_but_may_list` and five mutants, with the proof under optimization above.
- **Round 4** raised no finding.

**Assumptions.**
- **Case count.** The acceptance's "same case count" was taken to mean that the default runs all 132 existing cases. The seven new cases, which the mutation evidence for the selection itself requires, raise the count to 139. Evidence: every existing name is in `--list`, and the round-4 review found all 88 integration bodies unchanged.
- **Name format and order.** `group/slug` names, the suite's order for a selection, and running a repeated name once follow the runner's own `--only`. These are non-material and are documented in the module docstring.

**Limitations.**
- **Double faults.** A mutant that breaks both the default selection and its check survives (CHK-02 to CHK-04). The check makes a faulty default fail explicitly rather than prove itself correct.
- **Hidden names.** A mutant that stops failures being printed or named leaves the run failing with exit 1, but without the name that would say which case caught it.
- **Renaming.** A table case's name follows its description, so editing a description renames the case.
- **Deadline cases under load.** The four short-tool deadline cases give their stand-ins 2 s and failed spuriously when three or four verifiers ran at once. A single verifier run, as README describes, passed each time it was run here.
- **Optimization.** Running the verifier under `-O` or `PYTHONOPTIMIZE`, previously hollow, is now refused, except for `--list`.
- **Locale.** The verifier stays locale-dependent (NB43) and was run under `C.UTF-8`.
- **Real Xcode.** No real-Xcode campaign was run, since the runner did not change.
