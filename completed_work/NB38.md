# NB38 — The runner's copy is one walk of the index

**Origin:** a design proposal from [S2](S2.md)'s review on 2026-09-25, recorded in TODO as not independently validated: `build_copy` composed `git archive HEAD`, the paths `git diff HEAD` named filtered through the index, and removal-first ordering, and four S2 review rounds had found Blocking defects in that composition. The user adopted the proposal on 2026-09-26 by instructing that NB38 be executed, before NB33 and NB35. Acceptance: every existing copy-building verifier case passes unchanged, and every behavior a removed step carried has an explicit owner with verification.

**Boundary:** replace the copy's construction with one walk of `git ls-files --cached`, mirroring each indexed path from the working tree with the existing file and symlink checks; leave named untracked files, `--out` handling, planning, and everything after the copy unchanged. NB33–NB35, NB39–NB41, S3, S4, and any change to verdicts, locks, or reports were out of scope. Validation was the unchanged verifier cases, a comparison of this repository's copy under both designs, mutation evidence against the unmodified verifier, a real-Xcode run, AGENTS' gates, and the review skill's full procedure.

**Premise check.** At `257938f`, this repository has no `.gitattributes`, no submodule, no assume-unchanged or skip-worktree entry (`git ls-files -v` reports `H` for every path), and no tracked file containing a CR byte, which are the places where the two designs can differ. A copy built by `HEAD`'s `build_copy` and one built by the index walk were identical at `HEAD` and again on the final dirty candidate: 174 entries, equal `tree_digest`, equal `lstat` modes, and `diff -r --no-dereference` clean. The proposal therefore reaches the same state for this repository.

**Change.** `build_copy` starts from an empty copy and walks the index once, NUL-separated and deduplicated, because an unmerged path is listed once per stage. A path beneath a working-tree symlink is skipped, as before. `mirror` copies a file with its mode (`copy2`), recreates a symlink with its own target, leaves an absent path absent, and refuses anything else, now including a gitlink whose working-tree entry is a directory. It no longer removes an existing destination, because the copy starts empty and each path is written once. README describes the new copy.

**Behavior owners.** Each removed step's behavior and what now owns and verifies it:

- `git archive HEAD` supplied the content, modes, and symlinks of clean tracked paths. The walk now copies them exactly as it copies changed ones, so the cases for changed paths hold both: `results_identify_their_run` changes an executable bit, `a_changed_symlink_is_copied_as_a_link_not_followed` a symlink, every case that reaches the test tool needs the fixture's clean files, and `edit_paths_stay_inside_the_copy` needs its clean `Sources/Escape` symlink. The archive also applied export attributes, which no longer reach the copy: `every_indexed_path_is_copied_as_the_working_tree_holds_it` commits an `export-ignore` file and an `export-subst` file and requires both verbatim. Checkout conversions such as end-of-line attributes and smudge filters are already in the working tree's bytes. For a committed gitlink the archive produced an empty directory; the walk refuses a gitlink whose working-tree entry is a directory, held by `a_tracked_submodule_is_refused`, and omits an absent one. Modification times now come from the working tree instead of the commit; `tree_digest` excludes them.
- `git diff HEAD --name-only --no-renames -z`, filtered through the index, carried dirty content (the stand-in test tool asserts `Sources/Dirty.swift` in every run it starts), deletions (`a_file_deleted_in_the_working_tree_is_absent_from_the_copy`), staged and quoted paths (`paths_git_quotes_reach_the_copy`), renames (`a_staged_rename_leaves_no_old_path`), a path removed from the index but left on disk (`a_file_removed_from_the_index_but_left_on_disk_is_not_copied`), type changes (`a_directory_replaced_by_a_file_becomes_that_file`, `a_tracked_symlink_replaced_by_a_file_is_not_written_through`, `a_tracked_file_replaced_by_a_directory_refuses`), and the symlink-ancestor rule (`a_tracked_directory_replaced_by_a_symlink_is_not_followed`). Git's view of which paths changed no longer decides anything: the new case's assume-unchanged file must reach the copy with its working-tree edit. The diff named a conflicted path once, where the index lists it per stage: `an_unmerged_path_is_copied_once` stages three entries for a symlink.
- Removal-first ordering, and `mirror`'s removal of an existing destination, served the overlay onto the archive. With an empty copy nothing is removed: a staged case-only rename leaves only the new spelling in the index (`a_case_only_rename_survives_the_copy`), and a rerun starts from nothing (`a_rerun_rebuilds_the_copy_from_the_current_target`). The cases that held unlinking a symlinked destination and removing a directory at one still pass, because no destination exists; S2's mutants of those steps have no code left to mutate.
- Untracked and ignored content stays out because the index lists neither: the stand-in's `ignored.log` assertion, `omitted_tests_and_untracked_take_their_defaults`, and the `--others` mutant below. Byte-exact content is `copy2`'s, held by `edits_and_restore_preserve_exact_line_endings`.

**Verifier.** `./verify-mutation-runner.py` passes 94/94 on Python 3.13.9 and on `/usr/bin/python3` 3.9.6: the 91 existing cases, unmodified, and the three new ones. `HEAD`'s runner fails exactly the export-attribute case and the submodule case (92/94); the unmerged case passes there, because the diff listed each path once.

**Review.** One round. Codex `gpt-6-sol` with high reasoning effort, dispatched through the skill's Claude Code route (`codex exec --dangerously-bypass-approvals-and-sandbox`), reviewed the frozen candidate after its gates passed; the repository matched its freeze snapshot afterwards (status and SHA-256 of all four changed files), no reviewer process remained, and it left no scratch artifacts. Its verification rebuilt the candidate from `git archive HEAD` plus the four changed files, ran the verifier (94/94 on `/usr/bin/python3`), and confirmed that `HEAD`'s runner fails the export-attribute and submodule cases and that removing deduplication fails the unmerged case. It reported **no Blocking and no Non-blocking findings**. Its one **Nit**, fixed, was that README's "a submodule is refused" overstated the check: a gitlink is refused only when its working-tree entry is a directory, is omitted when absent, and is copied when a file or symlink stands there. README now says an indexed path the working tree holds as a directory, such as a submodule, is refused. It dismissed, as consistent with the boundary, that file and symlink entries at a gitlink's path are copied as the working tree holds them. The fix changes one README sentence; the runner and verifier are byte-identical to the reviewed candidate, so it was verified by the diff rather than by another review, as S2's eleventh and thirteenth rounds did for wording.

**Main-agent validation.** Nit (README submodule wording): **Validated** by reading `mirror`: it raises only when the source exists and is neither a file nor a symlink, and an absent source yields nothing; the new wording matches that.

**Limitations.** On a case-insensitive volume, an index holding two spellings of one symlink now ends the run with an `OSError` refusal ("File exists") and exit 2 rather than copying it once, as a scratch probe of `build_copy` showed; this repository's index holds no such pair, and no case exercises it. A path Git lists that is not valid UTF-8 is refused by the listing's strict decoding; this volume, APFS, refuses such names with `EILSEQ`, so none can stand in the working tree. Skip-worktree paths absent from the working tree are omitted by the same rule as a deletion, and with `core.filemode` false the working tree's executable bits are copied; neither is exercised, and this repository uses neither. On a case-sensitive volume the verifier's alias and case-only-rename cases return without asserting, as S2 recorded. The real-Xcode run selected one suite.
