# NB25 — Provider-only metadata invalidation has its own test

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB25 — Fixed.** The provider half of `updateSettings`' metadata-scope comparison now has a test that fails when it breaks; the guard itself was already correct and is unchanged. OpenAI and a Custom provider with no saved endpoint share OpenAI's speech endpoint, so switching between them changes the provider alone. `TTSNetworkManagerMetadataSourceTests.testAProviderOnlySwitchInvalidatesMetadataFetchedForTheSameEndpoint` holds an OpenAI model discovery open, first applies a key, model, and voice edit within the same provider and endpoint, which must leave that discovery running, its token current, and both lists published, and then switches to Custom on the same endpoint. That switch must cancel the discovery, release both metadata slots, clear both lists before `updateSettings` returns, and refuse late model and voice publications carrying the old tokens. The same-scope edit is what attributes the invalidation to the provider rather than to any edit. Ten mutants were run against six metadata and Settings suites in an isolated scratch copy, against an unmutated control that passed, and each fails a named test. Dropping the provider from the comparison, which had survived the whole suite at `3c2007b`, and comparing only whether the protocol family changed (Gemini or OpenAI-compatible) fail the new test alone. Invalidating on every edit, on a key edit, or on a model edit fail it too, and the every-edit and model-edit mutants also fail hosted `SettingsVoiceMetadataTests` cases. Dropping the endpoint from the comparison still fails `TTSNetworkManagerMetadataLifecycleTests.testScopeChangesCancelThePendingModelRequest`. The new test's assertions are each load-bearing: dropping the cancellation, the model-slot release, the voice-slot release, or the list clearing fails it, along with other existing tests for three of the four. It passed 50 consecutive iterations. README's statement that only metadata for the still-selected provider and endpoint may update the UI already describes this behavior.
