# B2 — Underrun recovery

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**B2 — Fixed.** The progress tick still stops playback at the end of the buffered PCM, but `AudioPlayerManager.stopAtBufferedEnd` now records why, and only one of the four reasons is undone by the PCM that arrives behind it. A stream whose request has published `streamTermination` has been heard to its end and stays stopped; a stream still open has run dry, so `underrunSuspendedGeneration` names it and the next chunk `scheduleAudio` puts on the node resumes it in the same main-queue turn that publishes the grown buffer. The node was paused rather than stopped, so resuming plays on from its own sample time: nothing already heard is rescheduled and no second prebuffer window opens. The tick discounts however far the rendered position overshot the buffered end while the node ran dry, because that silence is not audio anyone heard and carrying it forward would put each resumed position a further tick ahead of the sound and stop the next underrun early. The menu's Pause, a seek, `stop()`, and a replacing stream each release the suspension, so a decision the user made is never reversed by late audio. Whether playback has reached the end is decided against that serialized frame count rather than the published `bufferDuration`, which lands a main-queue turn after the frames it counts reach the node: judged against the lagging value, a stream already rendering its next chunk looks as though it ran dry, and the frames it had heard of that chunk would be discounted as silence. `isNodePlaying` reports what the player node is actually doing so tests can hold the published state to it; nothing in the app reads it, because the node is never the app's source of truth for what is playing, but a resume that published playback without restarting the node would otherwise satisfy every assertion. Seventeen mutants were run: reverting to an unconditional final stop, treating a terminated stream as resumable, making Pause resumable, letting a seek keep the suspension, dropping the offset re-anchor, resuming without the progress timer, resuming by re-seeking, resuming on every chunk, failing to consume the suspension, deciding the end against the published duration, anchoring to it, requiring the rendered position to pass the end rather than reach it, resuming without restarting the node, and suspending without pausing it each fail a named test. Removing `stop()`'s clear and removing the suspension's generation comparison each survive alone and are equivalent by construction — `stop()` only ever advances the generation, so a value left behind can never equal a later stream's — while removing both fails the replacement-stream test; both are kept, matching how the sibling automatic-playback generations are cleared. `AudioPlayerManager` gained an extension owning this end-of-stream state machine, because the class body was already at its `type_body_length` limit and these members are one responsibility rather than a split for length. README owns the current contract. NB9 later paired a live format change with its request's cancellation.
