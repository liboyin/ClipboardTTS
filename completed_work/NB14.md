# NB14 — Model and voice edits apply once and refresh only what they change

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB14 — Fixed.** Each model and voice row in `ModelVoiceConfigurationView` now observes its binding once rather than once per control, so typing and choosing from the picker each apply an edit once. `SettingsView.syncSettings` now takes flags for which lists to refresh. For OpenAI and Gemini, opening the window and provider and API-key edits still rediscover models and republish the voice catalog. A Custom endpoint edit applies the configuration without discovery, as before. A model edit republishes only the voice catalog, after the manager holds the new model, because only the OpenAI catalog follows the model. A voice edit refreshes neither. Assumption recorded in the boundary: a failed discovery is no longer retried by typing a model, only by reopening Settings or editing the provider, endpoint, or key. The manager's metadata guards and invalidation are unchanged. Thirteen mutants were run in an isolated scratch copy against an unmutated control that passed. Each fails a named test in `SettingsMetadataRefreshTests`: restoring either picker's duplicate observer, running a full sync for a model or a voice edit, skipping the model edit's catalog refresh or running it before the configuration is applied, applying nothing for either edit, observing only through the pickers, dropping the key edit's discovery, turning discovery off by default, swapping the two callbacks, and reporting a model change as a voice change. README owns the current behavior.
