# NB6 — Linear Gemini SSE parsing with a 64 MiB event cap

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB6 — Fixed (D13).** `GeminiSSEEventParser` now keeps a cursor over the bytes it has already searched. Each received byte is searched for a line ending once, the consumed prefix is dropped once per packet, and an event's data lines are joined in linear time. One event may occupy at most 64 MiB before it ends. It is charged the raw bytes of its data lines, `data:` included, plus any line still unfinished, without line feeds. The charge is checked as each line completes and between callbacks, so where URLSession splits the stream cannot change whether an event fits. An empty data line costs five bytes, and the charge is never smaller than the joined payload. An event over the cap fails the stream as the packet arrives, on the existing malformed-event revocation path. The cap's evidence was re-verified 2026-09-18 and is recorded in D13 and README. Google's model pages give 16,384 output tokens, and its pricing page bills 25 audio tokens per second, so the largest documented event is about 42 MB. The speech-generation guide says only the 3.1 model streams TTS, so a 2.5 model sends that whole event at once, and the old per-packet rescan was quadratic on real traffic. The first adversarial review found two Blocking gaps in the first candidate, and both reproduced in a probe. The cap was checked only after a callback, so an event ending in that callback escaped it. Only data values were charged, so empty data lines grew an event without bound. Thirteen mutants were run against the three Gemini suites in an isolated scratch copy, with an unmutated control that passed, and each fails a named test. Searching from the line start again fails both search-count tests. Removing the cap, either of its two checks, or the current line from the in-loop check each fail a named test. So does making either check strict, charging only values, or not charging data lines at all. Leaving the charge unreset, lowering the cap to 32 MiB or raising it to 128 MiB, or swallowing the refusal in the caller each fail one as well. The manager-level tests hold the mock response open, so end of stream cannot fail the event with the same message instead. The over-cap event they finish is well-formed JSON, so a missed cap would deliver audio rather than fail as malformed. They state D13's 64 MiB rather than reading the production constant, so raising the cap fails them. Earlier versions let mutants survive, and a second review found that the raised-cap mutant had not been run. Per-packet prefix removal and the linear join carry no mutation claim, because time is their only symptom. Fields other than `data`, and memory used after an event completes, remain out of scope. README owns the current behavior.
