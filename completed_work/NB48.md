# NB48 — A checked-in test protects the request helper's quiescence step

**Group:** NB48, NB49 and N8 change the same helper and its one call site, so they landed as one cohesive candidate with one integrated review; the [NB48 record](NB48.md) holds the shared validation, mutation evidence and review. All three came from the main agent's read-only gap review of its 2026-10-12–13 session changes, and the user asked on 2026-10-13 to fix them. D24, the user's standing approval of loopback-isolated routing mutants, was recorded in TODO in the same commit.

**Origin:** [NB46](NB46.md)'s gate and barrier were exercised only by probe tests that existed in scratch copies. The helper's one call site never times out, so removing the gate, the barrier or both passed every checked-in test and gate.

**Boundary:** a checked-in, deterministic test fails when the gate, the barrier or both are removed. It uses controlled scheduling rather than sleeps, and scopes the expected timeout with an `issueMatcher`. A narrow, documented test-only seam in the helper was allowed. Test-only.

**Change:** `Tests/QuiescentRequestTests.swift` adds two tests:

- `testACompletionRunningAtTheBarrierFinishesBeforeTheHelperReturns` holds the completion between its decision and its fulfilment until the helper's wait has expired. It then gives a broken helper up to 1 s to return wrongly; a correct helper passes however short that window is.
- `testACompletionDeliveredAfterTheBarrierRecordsNothing` suspends the session's delegate queue so delivery waits until the helper has returned. It then resumes the queue, joins it, and asserts the late completion recorded nothing.

The seam is `RoutedRequest.Observer`, which the helper takes as a defaulted parameter that its other call site omits. It has three hooks:

- `sessionCreated`: called once the helper has built its session.
- `completionDecided`: called on the delivery queue after the gate decides, before fulfilment.
- `beforeWait`: called on the calling thread after the task starts and before the bounded wait.

The test class also overrides `record(_:)` to signal when the expected timeout is recorded. Each test joins the delivery queue before reading what the completion wrote, including when a broken helper returns early.

**Review round 1 (R1, Blocking):** in the first round, the running-at-barrier test began the 0.2 s wait without first establishing that its completion had arrived. A delivery later than the wait would then fail correct code; the reviewer showed this with a delayed-delivery probe. The main agent validated the finding and fixed it with the `beforeWait` hook. The test now blocks there until the completion has entered and holds the delivery queue, so the wait always starts with the completion in flight. Delivery is bounded only by the 10 s safety bound.
