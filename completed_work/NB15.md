# NB15 — The coverage gate fails closed

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB15 — Fixed.** `check-coverage.sh` now enumerates the gated sources on disk and compares a percentage only once the report has been found to measure exactly that population: every gated source present, none counted that is no longer on disk, none counted twice, and each carrying at least one executable line. A population it cannot measure exits 2 — the gated directory absent from disk, the target absent from the report, a gated source omitted, counted stale, duplicated, or measured at zero executable lines — while coverage that was measured and fell short still exits 1, and a refusal prints no PASS verdict. A report the script cannot read reaches that same exit 2 rather than the threshold's: a failed extraction, a body that is not JSON, and targets, a file list, or a file record that is not the shape xccov documents. A record is read for its path and its two line counts only, and its name comes from the last `/Sources/` component of that path; counts it cannot mean — a boolean, a negative, or more covered lines than executable ones — are refused there rather than averaged, while a fully covered and a wholly uncovered file stay ordinary readings. A group with no executable lines reads `n/a` rather than `100.00%`, which was the reading that let a 0/0 population pass. The exemption is not tightened: an exempt source may carry no executable lines, name a file no longer on disk, or be absent from the report, as `Sources/SettingsKeys.swift` is, declaring only string constants and appearing in no coverage record. The script additionally accepts a path ending in `.json` as an already-extracted report, and `verify-coverage-gate.sh` uses that seam to drive the real script end to end over twenty-seven synthetic reports with no build, bundle, or network. The first adversarial review found two Blocking gaps in the first candidate, both reproduced in a probe: the verdict summed every manager record in the report rather than the enumerated population, so a stale record for a deleted manager passed at 98.43% while all sixteen current gated sources sat at 0/1; and a report that could not be parsed exited 1 through an uncaught exception, which is the code that means measured-but-insufficient. Its Non-blocking finding — that `split("/Sources/", 1)` read the first `Sources` component, so a checkout under a `Sources`-named parent was refused as though every gated file were absent — was fixed in the same change by user decision on 2026-09-20. A second review then found that the record validation accepted counts no report can mean: `-1/-1` and `true/true` each passed at 100% and `2/1` at 200%, because Python reads a JSON boolean as an integer and nothing bounded the two counts against each other. Twenty-seven mutants were run in an isolated scratch copy against an unmutated control that passed, and each fails a named case: reverting the missing-source, stale-source, duplicate, zero-executable-line, empty-population, JSON-parse, targets, file-list, record-object, record-path, record-count, count-range, or extraction guard; reverting the boolean rejection, the `n/a` reading, or the last-`/Sources/` normalization; enumerating a different directory, an enumeration matching nothing, leaving the enumerated `Sources/` prefix in place, and letting a failed enumeration abort rather than fail closed; running the four population guards after the verdict instead of before it; and, as over-restrictions, applying the zero-line check to every group, requiring every source rather than every gated source to be measured, refusing any record whose path is not on disk, requiring a record to carry fields beyond the three the gate reads, and requiring a file to be partially rather than fully or wholly uncovered. Which files are gated is unchanged and stays with NB16, whose acceptance now has this property to preserve. **Limitation:** the two scripts were syntax-checked with `bash -n`; shellcheck is not installed on this machine. README owns the current policy.
