# NB49 — The request helper refuses a configuration that is not routed

**Group:** NB48, NB49 and N8 change the same helper and its one call site, so they landed as one cohesive candidate with one integrated review; the [NB48 record](NB48.md) holds the shared validation, mutation evidence and review. All three came from the main agent's read-only gap review of its 2026-10-12–13 session changes, and the user asked on 2026-10-13 to fix them. D24, the user's standing approval of loopback-isolated routing mutants, was recorded in TODO in the same commit.

**Origin:** `completionError(of:configuration:…)` built its own `URLSession` from whatever configuration its caller passed, so `.default` or `TTSNetworkManager.sessionConfiguration(routing: nil)` would load the request through the system's own HTTP loader. README also said network tests create sessions only through `TestNetworkFactory`, which the helper contradicted.

**Boundary (user choice):** the helper asserts the configuration is routed. If it is not, the helper records a failure and creates no session or task. README states the helper's exception to the factory rule.

**Change:** `RoutedRequest.isRouted(_:through:)` requires the configuration's first protocol class to be a `URLProtocol` that is not one of a fresh ephemeral configuration's classes, compared by identity before `canInit(with:)` is asked, and that claims the request. Otherwise the helper records `RoutedRequest.unroutedConfigurationFailure` and returns without a session. README's factory sentence now names `sendOneRoutedRequestLeavingNoCompletion` as the one exception and gives the reason.

The following was verified on this machine. The ephemeral and default configurations list the same system protocols: `_NSURLAppSSOProtocol`, `_NSURLHTTPProtocol`, `_NSURLDataProtocol`, `_NSURLFTPProtocol`, `_NSURLFileProtocol` and `NSAboutURLProtocol`. Only `_NSURLHTTPProtocol` claims an http loopback request.

Three tests cover the refusals: an unrouted configuration, a system protocol first that would claim the request, and a test protocol first that declines it. Each scopes the helper's message with an `issueMatcher` and observes directly that no session was created. A pure check confirms that the refusing and mock routing count as routed.

**Validation, mutation evidence and review:** see the [NB48 record](NB48.md); NB49's mutants are the `nb49-*` rows there.

**Limitations:** the check examines only the first protocol class, which is the one URLSession offers the request to first. A routed configuration's later classes are not inspected.
