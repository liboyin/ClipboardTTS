# NB11 — Audio engine start failures and configuration changes

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB11 — Fixed (D10, D11).** NB11a made an engine-start failure its own error, separate from the format error. Every start now publishes through one owner that clears the failure on success, and a new session retries a stopped engine instead of refusing. NB11b makes the player observe `AVAudioEngineConfigurationChange` for its own engine, on the main queue. A change pauses the session at its position the way Pause does, restarts the engine, and reschedules the remaining PCM from there. A Play that has to start a stopped engine reschedules the same way. The change is counted on the posting thread, so an automatic start or underrun resume already queued on the main queue stands down until recovery runs. An underrun resume also never plays a stopped engine's node. README owns both contracts. **Limitation:** automated tests use an owned engine and notification center. A physical output-device switch and macOS 13 were not exercised. **Revisit if** a real device change shows the engine does not stop, or needs its graph reconnected for a new hardware format.
