**Origin:** the 2026-09-06 full-project review (legacy Task 46). `TextExtractionManager.getCopiedText()` printed whether the clipboard held text. The messages disclosed clipboard presence, not copied text, and had no release purpose. D8 decided to remove them.

**Revalidation at `baac92d`:** both `print` calls were still in `getCopiedText()`, and they were the only console output in `Sources/`. No README or USER_STORIES text described them. The existing empty-clipboard test injected `nil`, so no test reached the `!copiedText.isEmpty` branch.

**User decisions (2026-10-27):**

- **D25:** no test can observe a reinstated print, because stdout is shared with the test runner. So the removal is kept by a strict SwiftLint rule refusing free `print`, `debugPrint` and `NSLog` calls in `Sources/`, leaving `Tests/` free to print. This follows NB47's lint-guard precedent. It is recorded in TODO.
- **Review R1-F1:** fix now (see Review).

**Boundary:**

- Remove the two prints and keep the function's shape.
- Add the D25 rule `production_console_output`.
- Test the empty-string branch of the edited function. The assumption was that "preserve populated/empty returns" covers an empty string as well as `nil`.
- Compatibility: `getCopiedText()` still returns injected non-empty text exactly, and `nil` for a `nil` or empty pasteboard. Menu, Settings, Services, persistence, provider-request and audio-session contracts are untouched.
- Non-goals: no new error, no alternative logging, no change to `PasteboardReading` or `GeneralPasteboardReader`, no ban on prints in `Tests/`, nothing for NB27.

**Change:**

- **`TextExtractionManager.swift`:** the two prints are removed.
- **`.swiftlint.yml`:** the `production_console_output` rule covers `Sources/` only and skips comments, doc comments and strings. It refuses a free `print(`, `debugPrint(` or `NSLog(` call, bare or `Swift.`-qualified however it is spaced. It does not refuse a member call (`x.print(`, `x . print(`, or `.print(` on a continued line), a `func print(` declaration, or a longer identifier. Its comment states the rationale and what a regex cannot catch: a function reference, an alias, or another logging API.
- **`TextExtractionManagerTests`:** `testTextExtractionTreatsOnlyAnEmptyStringAsNoText` checks that an empty string reads as no text and that a one-character string is returned.

**Limitations:**

- The rule is a regex over known spellings, not a proof. A function reference (`let log = print`), a type alias, a comment spliced into the call, and other logging APIs (`os_log`, `Logger`) still get through.
- A member call separated from its `.` by more than 20 whitespace characters would be refused.
- No live app run checked the console. The evidence is the source search, the lint rule and the build.
