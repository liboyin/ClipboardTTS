# NB4 — Redirect transport and credential rules

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB4 — Fixed.** A redirect now answers to two rules rather than one, and `TTSNetworkManager+Redirects` owns both. The target's transport is decided first, so a cleartext target still reports the endpoint failure whose remedy Settings documents, even though it is a foreign origin as well; a target that is protected but not the origin the request was built for is refused as its own failure, which names neither the configured endpoint nor the provider-controlled address it refused. `EndpointTransportPolicy.isSameOrigin` decides that origin from scheme, host, and effective port — scheme and host read case-insensitively, an omitted port as the scheme's default, and a URL it cannot read an origin from matching nothing, its own repetition included. The scheme is compared in its own right even though the default port a scheme implies usually separates two spellings already: on loopback, where both schemes are permitted and the port is stated, it is the only thing that does. A redirect the app does follow is not passed on unchanged either, because the credentials URLSession leaves on the request it builds are not the ones the app authorized: probed on Xcode 26.6 (CFNetwork 3860.700.1, Darwin 25.6.0) against a loopback server, it forwards this app's `x-goog-api-key` header and the POST body holding the user's clipboard text across a cross-origin redirect, while stripping `Authorization` from every redirect it builds, a same-origin one included — so following one unchanged both leaked a key and broke authentication on an ordinary provider path move. Each field in `CredentialHeaderField.all` is therefore restored from the request the app itself created, which puts back the one that request authenticates with and removes any other the response introduced; the request is copied rather than rebuilt, because the body URLSession replays is not visible on it — a test can hold that copy to the method and content headers it carries, and the probe is what says the body rides along with them. Both halves of the decision come from that request rather than from settings the user may have edited since it started, which is the rule the bounded retry already follows when it replays the request it sent: the origin a target is compared against, and the credential a followed target is given, are the ones the request was built with, so an endpoint saved mid-stream authorizes nothing for it and a newly typed key never reaches the origin it was not issued for. A refusal is recorded only against the speech request that owns the refused task, so discovery redirecting while speech streams leaves that stream to finish on its own response, and a refused discovery request stays as silent as every other metadata failure. Twenty-two mutants were run: removing the origin check, removing the restoration, restoring only one of the two credential fields, restoring without removing an unauthorized one, deciding origin before transport, giving both refusals one message, refusing every redirect, comparing whole URLs, ignoring scheme, host, or port, dropping the default-port normalization or misreading it, comparing scheme or host case-sensitively, giving a scheme the app never sends over a port anyway, reading a URL's own port before deciding whether the app sends over its scheme, recording a refusal against whichever request was active, taking the compared origin or the restored key from current settings instead of the request that started, and rebuilding the redirect request instead of copying the one URLSession built each fail a named test. The probe is a reproduction recipe rather than a checked-in test, and it exercised loopback HTTP only: no live provider, and no HTTPS redirect chain, was driven. README owns the current contract. NB7 still owns the endpoint-substring provider inference that decides which credential header a request carries in the first place.
