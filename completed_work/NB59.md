# NB59 — Each keystroke in an API-key field writes the Keychain

**Origin:** the second full-project review on 2026-11-03, at `23a88719e6fa848f212efd6d07197d912b2ce87d`, by source inspection. `SettingsView.secretBinding` (`Sources/Views/SettingsView.swift:380`) saves on every edit, so typing a key issues one Keychain update or add per character through `SettingsSecretState.saveSecret` (`Sources/Views/SettingsSecretState.swift:84`); clearing the field deletes the item, and every edit also reapplies settings. The review raised, as an untested hypothesis, that ad-hoc-signed releases might multiply Keychain access prompts.

**Superseded decision:** D33 (2026-11-03) chose a Save button. Expanding it exposed two user-visible questions: whether an unsaved draft reaches requests (Test Voice, menu, Services), and what an edited but unsaved field shows when Settings closes or switches provider.

**Accepted without change (D35, user decision, 2026-11-03).** The user withdrew D33 and kept saving on every keystroke, because it leaves the user no decision to make and therefore nothing to be confused about. The current contract stands: the next clipboard, Services, or Test Voice request uses the key as typed.

**Validation:** no code or test changed, so no gates, mutation runs, or review were needed (AGENTS' documentation-only exemption). The existing confirmed-write behavior and its tests are unchanged.

**Limitations:** the Keychain-prompt hypothesis was not tested against an ad-hoc-signed rebuild.

**Revisit if** typing a key is seen to raise repeated Keychain prompts, or Keychain writes per keystroke cause another observed problem.
