# NB26 — The unrouted production-policy manager stays inside the test factory

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB26 — Fixed.** No test can obtain a manager whose session reaches the real network. `ManagerSessionConfiguration.productionDefault` now carries an `UnroutedSessionToken` whose initializer is `fileprivate` to `TestNetworkSupport.swift`, and that file uses it only in `TestNetworkFactory.productionDefaultSessionPolicy()`, which builds the manager through `makeManager`'s one construction path and returns only its session's configuration. The policy test's five assertions therefore still read the session a manager builds when given no configuration, and that manager is registered and torn down like every other factory manager. The acceptance criterion that a request issued from that manager fails locally does not apply, because no test holds the manager. Mutants were run in an isolated scratch copy against an unmutated control that passed. Reverting the manager's default to `.ephemeral`, which is NB5's revert, and inspecting a mock-routed manager instead each fail `TTSNetworkManagerSessionPolicyTests.testProductionSessionPolicyDisablesPersistenceWhileRetainingMockRouting`. Constructing the token from another test file fails to build on its access level, and builds once the initializer is made internal. An over-restriction does not apply, because the change adds no rule a correct manager could violate. A first candidate gave the helper its own copy of the construction, which left its session registration unprotected; routing it through `makeManager` removed that copy, and the run exposed NB30. `AppStartupDependenciesTests` also builds managers on the production policy, through `AppStartupDependencies.make`, and was outside this finding. README owns the current rule.
