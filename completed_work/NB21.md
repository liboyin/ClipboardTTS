# NB21 — Hosted Settings controls and their test layers

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB21 — Accepted without change (D20, 2026-09-21).** The inventory its investigation gate required, taken at `2294288` and unchanged through `3c2007b`, which touched neither layer. `SettingsActionButton` is the only Settings control a windowless `NSHostingView` renders as something a test can press: SwiftUI draws its own buttons there and publishes no accessibility tree, and wrapping the host in an `NSWindow` is forbidden because AppKit window teardown can outlive the test. Eight test files drive one — Test Voice in `SettingsViewTests`, `SettingsAudioFormatTests`, `SettingsVoiceMetadataTests`, `SpeechEntryPointSessionTests`, `TTSNetworkManagerAuthenticationTests`, and `SettingsMigrationRecoveryTests`; both recoveries in `SettingsMigrationRecoveryTests` and `SavedKeyReadRecoveryTests`; About in `SettingsAboutTests` — across exactly forty presses and `rendersButton(titled:)` probes, and that probe is the only way a test states that a conditional action is deliberately absent, which clicking cannot express because a missing control fails instead. It also owns the standard push-button appearance (`bezelStyle = .rounded`, what `.buttonStyle(.bordered)` draws) and the `.fixedSize()` hugging `SavedKeyRecoveryView` applies. Retiring it needs a UI-test target, which is a new interaction surface and therefore needs its own agreed boundary rather than riding along with a simplification, so the wrapper is kept. `AboutAction`'s three protocols each own something distinct: `BundleInfoReading` stubs the Info.plist so the shipped `BundleAboutMetadata` can be held to the key names it reads against values no real bundle carries; `AboutMetadataProviding` is the seam a hosted Settings test injects to prove the rendered control routes fixed values to the panel without reading the host bundle; and `AboutPanelPresenting` is what keeps a modal AppKit panel out of the suite, which is also the boundary the coverage gate's `StandardAboutPanelPresenter.showAbout(applicationName:applicationVersion:)` exclusion sits on. Collapsing the metadata pair into `AboutAction` was considered and refused: it would trade one protocol and one struct for moving the bundle read to when Settings is built rather than when About is clicked, and for the loss of the seam that keeps that hosted test off the host bundle. **Observed while inventorying, not a defect:** `BundleAboutMetadata`'s two fallbacks — `CFBundleName` to the process name, an absent `CFBundleShortVersionString` to the empty string — are the only unexecuted expressions in `Sources/AboutAction.swift` outside the excluded presenter, because every test supplies both keys. **Revisit if** a UI-test target is agreed, which would give the hosted control presses another owner, or if the About exclusion's boundary moves for another reason.
