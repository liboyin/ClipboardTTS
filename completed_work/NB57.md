# NB57 — The packaged app runs only on Apple silicon

**Origin:** the 2026-11-03 second full-project review, at `23a8871`. `lipo -archs` on a local `package.sh` product reported only `arm64`, `package.sh` passed no destination or `ARCHS`, and neither README nor USER_STORIES stated an architecture, so an Intel Mac user would get an app that cannot launch, with no warning. The review did not establish why `x86_64` was missing.

**Accepted boundary and decision:** D32 (2026-11-03): the app does not support Intel Macs and is distributed for Apple silicon only. Intent: README's Requirements and Packaging sections state that, and the `arm64`-only build stays as it is. Non-goals: changing `package.sh`, `project.yml`, the build's architectures, or USER_STORIES. Validation: check the stated requirement against `lipo -archs` on a current Release build. Done when README states the requirement in both sections and the statement matches that build.

**Revalidation and cause:** at `69e5e29` on Darwin 25.6.0 (Apple silicon), Xcode 27.2 (27B52), a clean Release build with `package.sh`'s exact `xcodebuild` arguments, into scratch derived data rather than `build/`, succeeded, and `lipo -archs` on its `ClipboardTTS.app/Contents/MacOS/ClipboardTTS` reported `arm64`. The cause is the implicit destination, not the toolchain's standard architectures: `xcodebuild -showBuildSettings` for Release resolves `ARCHS_STANDARD` and `ARCHS` to `arm64 x86_64` with `ONLY_ACTIVE_ARCH = NO`, but the build log reports `Using the first of multiple matching destinations` (`platform:macOS, arch:arm64, name:My Mac` before the `x86_64` one), exports `ARCHS=arm64`, and compiles only `-target arm64-apple-macos14.0`. A package built on an Intel Mac would therefore presumably hold that Mac's architecture instead; that was not tested.

**NB57 — Fixed (D32).** This was a documentation-only change to `README.md`. Requirements now says the app needs a Mac with Apple silicon and does not run on Intel Macs. Packaging says `package.sh` names no destination, so `xcodebuild` builds for the first one it matches, `arm64` alone on Apple silicon, and that packaging belongs on Apple silicon.

**Validation:** the main agent checked both statements against the Release build above and the diff. As a documentation-only change, it is exempt from the application gates and formal adversarial review under AGENTS; none was run for this commit.

**Limitations:** the package's first-run instructions printed by `package.sh` still name no architecture, because changing the script was outside this boundary. Nothing was launched on an Intel Mac. The scratch derived data was deleted after the check.
