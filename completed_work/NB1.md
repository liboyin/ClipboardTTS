# NB1 — Response format validation

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB1 — Fixed.** A success response now has to say what it is before any of it is played. `SpeechResponseFormatPolicy` owns that decision for both provider paths and reads a declaration the same way for each: parameters dropped, case folded, and a value that is not one media type refused rather than parsed. Only an absent or blank header is silence; every other value is something the provider said and has to be a whole media type, its type and subtype both HTTP tokens. A header carrying several types, which is how URLSession presents a response that declared two, has not declared what its body is, and reading only as far as its first parameter would let its leading half excuse the rest. A value carrying only parameters, and a subtype such as `()` or an emoji, are refused for the same reason rather than read as silence: since the audio tree is accepted without inspecting the subtype, whether a value is a media type at all is the last thing standing between a provider-controlled header and the player, and an adversarial review found that gap open before this landed. An OpenAI-compatible or Custom body is judged by its `Content-Type` and the accepted set is deliberately open: nothing at all passes, because OpenAI's own reference documents no content type for `/v1/audio/speech`; any `audio/*` passes without inspecting the subtype, because which one a compatible server labels raw samples with is documented nowhere and narrowing it would refuse a working deployment on a guess rather than on evidence; `application/octet-stream` and `binary/octet-stream` pass as the generic spellings D4 names. Everything else is refused, which is what closes the finding: two bytes of JSON returned with HTTP 200 were being handed to the player, and bytes that are not samples are not silently unplayable but audibly wrong, since the player reads every one of them as a little-endian 16-bit sample and renders them as full-scale noise. The refused body is dropped the way a non-2xx body already is rather than cancelled, because cancelling would end the task with a URL error and give the request a second reason to fail that is the app's own doing; `TTSNetworkManager.unplayableResponseFormatFailure` then points at the endpoint instead of inviting a retry, since a request that succeeded and returned something other than audio is answering correctly for whatever is at that address, and it quotes neither the declaration it refused nor anything else the provider sent. It is reported after an HTTP status, which stays the more actionable cause, and before a transport error, which only says that a body the app had already decided to discard stopped arriving. Gemini takes none of that rule — `text/event-stream` is the correct declaration for its transport — and is judged instead on each part's own `mimeType`, where the accepted set can be exact because one fixed provider publishes what its speech output declares: `audio/L16`, as `audio/L16;codec=pcm;rate=24000`, and `audio/pcm`, the spelling Google's Live API uses for the same samples. A part declaring anything else is a malformed event on the existing fatal path, which is right for a blob type the schema documents as carrying images, video, PDFs, and text as well. A part declaring nothing is still decoded, because the request asks for the `AUDIO` response modality alone and refusing an undeclared part would trade a defect nothing has produced for the loss of every Gemini utterance if the field were ever omitted; a `mimeType` of another JSON type counts as undeclared for the reason a `finishReason` of another type does, while a readable declaration naming other media does not. Twenty mutants were run: reverting either path's check, passing the refusal through as false, publishing no message for it, refusing an absent content type, narrowing the accepted audio subtypes, refusing generic binary, refusing an absent or non-string inline declaration, applying the response rule to Gemini as well, letting a transport error outrank the refusal, dropping the data guard that keeps the refused body out of the player, comparing case-sensitively, keeping parameters, accepting a multi-valued declaration, accepting an unreadable one, skipping token validation, reading a parameters-only value as silence, and narrowing the token set below what HTTP allows each fail a named test. Moving the refusal ahead of the HTTP status survives and is equivalent by construction: the refusal is recorded only inside the branch that has already established a 2xx status, so no completion can carry both, and the two branches cannot both be reachable for one response. The exception is a data task delivering more than one response, which `multipart/x-mixed-replace` allows and no speech endpoint sends; the flags there behave as the sibling `isErrorResponse` already does. Sample rate is not validated against the configured format, and the accepted `audio/*` set for a configurable endpoint is not narrowed: both would need evidence this decision does not have. README owns the current contract. NB2 still owns the completion predicate that decides whether the audio that did arrive counts.
