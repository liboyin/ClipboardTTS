# NB17 — Test teardown owns every queued audio action and metadata publication

**Origin:** the 2026-09-06 full-project review's ownership trace found that fixed waits remained in Services, audio and metadata tests, and that draining a network delivery queue does not drain the player's buffer queue, its publications, or a pending automatic start. It was recorded as a missing guarantee, not as an observed escaping callback. Selected on 2026-10-13 with [N7](N7.md) under the grouped-task-execution workflow. On 2026-10-13 the user chose to take all of NB17 in this group, audio, Services and metadata, accepting that the metadata half might add a metadata-completion test seam to `TTSNetworkManager`.

**Revalidation at `54dc35b`:** a read-only inventory, checked against source, found that nothing owned an `AudioPlayerManager`'s lifecycle at teardown. Its `bufferQueue`, main-queue publications, automatic-playback scheduler and progress timer were not drained, cancelled or counted by anything, including `MockURLProtocolTestCase`'s scope teardown, which drains only the network manager's delivery queue. 22 test files built players inline, and Services, menu, Settings and one authentication test used the production `asyncAfter` start and run-loop timer. Fixed waits remained in `AudioPlayerManagerTests.swift`, `ServicesCoordinatorTests.swift` and the four `TTSNetworkManagerMetadata*` suites, and metadata's stale-result cases had no observable completion event.

**Delivery:** two independent candidates, each gated, reviewed and committed separately, after N7 (`b6c870c`): NB17a, audio and Services (`5b09517`), then NB17b, metadata (this record's commit). Each was implemented by its own agent in an isolated worktree and integrated by the main agent. One Codex reviewer session reviewed both.

## NB17a — audio and Services (`5b09517`)

**Boundary:** every test-created `AudioPlayerManager` gets a test-owned lifecycle — its automatic-playback scheduler, progress timer, audio-queue processing and main-queue publications owned by the test, completed explicitly, cancelled or drained unconditionally at teardown — and work arriving after teardown is counted locally and can neither record an issue in, nor write state read by, a later test. Fixed waits in the audio and Services suites are replaced by explicit completion, and a strict lint rule refuses construction outside the owner. Tests, lint configuration and README only; every production contract preserved. Non-goals: the metadata half, network-only fixed waits in `TTSNetworkManagerTests.swift`, `MockURLProtocolTests.swift` and `TTSNetworkManagerConcurrencyTests.swift`, replacing the real `AVAudioEngine`, and the network scope's accounting.

**Change:** `Tests/AudioPlayerOwner.swift` adds `AudioPlayerOwner` and its factories `makeOwnedAudioPlayer` and `makeAudioPlayerOwner`. The owner holds the automatic start and keeps the progress timer off every run loop unless the test injects its own scheduler, wraps every scheduler and observer a test does inject, observes configuration changes on a notification center of its own, and holds the player weakly so lifetime tests still work. Its teardown, registered with `addTeardownBlock` as the player is built, stops the player behind `stop()`'s `bufferQueue.sync` barrier, drops every held start without running it, invalidates the player's timers, drains the main queue, closes, and waits out a final audio-queue barrier; callbacks after that are counted in the owner's ledger and reach nothing of the test's. Every other construction site in 22 files now calls the factory, which the strict `test_owned_audio_player` lint rule enforces in `Tests/` outside the owner's file. Fixed waits in `AudioPlayerManagerTests.swift` (lines 22, 31, 40, 65 and the `waitForPlayback`, `waitForPlayingState` and `waitForBufferDuration` helpers) and `ServicesCoordinatorTests.swift` (91, 155) became synchronous assertions, the manager's processing and publication hooks, or the Services action observer. `Tests/AudioPlayerOwnerTests.swift` adds seven owner tests. README's test-ownership paragraphs describe the owner. N7's lifetime test was moved onto the owner at integration.

**Coverage change:** only `AudioPlayerManager.swift` moved, 98.90% → 96.24%. The newly uncovered lines are `init`'s production default closures — the `asyncAfter` prebuffer scheduler, the rendered-position reader, the run-loop timer scheduler and the no-op observers — which every test now injects. Three baseline mutants that made those defaults wrong all survived the full bundle at `54dc35b`, so no protected property was lost, only incidental execution.

## NB17b — metadata (this commit)

**Boundary:** the metadata suites wait for explicit publication or completion instead of elapsed time, and metadata publications queued by a request's completion cannot land after the test that caused them. The user authorized (2026-10-13) a narrow metadata-completion test seam in `TTSNetworkManager` if a stale-result case was otherwise unobservable. Settings suggestion lists, metadata discovery requests and D19's guarded token path preserved; any seam defaults to a no-op. Non-goals: metadata publication semantics, the Settings hosted-test lifecycle, network-only waits.

**Change:** `TTSNetworkManager` takes a documented `metadataCompletionObserver`, a no-op in production, plumbed through `TestNetworkFactory.makeManager`. It is told a `MetadataCompletion` (`kind`, `token`, and an outcome of `.published`, `.abandoned` or `.superseded`) once handling is final: from `publishMetadata`'s main-queue block after the assignment, or as `.superseded` when the token guard refuses, and from `finishMetadataRequest` with the guard's answer, on the caller's thread. The guard logic is unchanged. `Tests/MetadataTestSupport.swift` adds `MetadataCompletionRecorder`, which a test owns and which only counts reports once closed, and `MetadataTestCase`, whose `expectPublication` drains the main queue and skips the replayed list, whose `waitForCompletions` waits for a report and then the main-queue turn a publication would take, and whose teardown closes the mock scope, drains the main queue and only then closes its recorders. The four `TTSNetworkManagerMetadata*` suites subclass it, and their fixed waits became publication expectations, completion waits, or direct assertions for synchronous refusals. README's network-test paragraph describes the metadata synchronization. The helpers were first placed in `TTSNetworkManagerMetadataTests.swift` because the implementation's edit boundary named only the four suites; at the main agent's request they moved into the support file before review.

**Review round 1 (R1, Blocking):** nothing retained protected the teardown's drain-then-close. The reviewer's mutants removing the drain, closing before the drain, and never closing each survived the 21 metadata tests, and a scratch-only probe that drove a `MetadataTestCase` scope's own `setUp` and `tearDown` killed all three; the implementation agent had recorded that teardown as unobservable without nested XCTest runs, which was wrong. The main agent validated the finding against the reviewer's results and added `Tests/MetadataTestSupportTests.swift`, a plain `XCTestCase`, since the `MetadataTestCase` scope each test drives opens and closes the mock-network scope itself, adapted from the reviewer's probes: `testTeardownRunsAQueuedPublicationBeforeClosingItsRecorder`, and `testClosingTheMockScopeWaitsForADiscoveryCompletionAlreadyInFlight`, which retains the scope-shutdown property the teardown relies on.

**Coverage change:** `TTSNetworkManager+Metadata.swift` 98.76% → 98.83%; `TTSNetworkManager.swift` 98.91% → 98.56%, whose uncovered lines are `init`'s default closures (the request-body encoder and the existing observers' no-ops at 142 and 145–146), the same pattern NB17a accepted.
