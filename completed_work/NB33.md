# NB33 — A terminal's Ctrl-C can no longer cut the runner's restore short

**Origin:** reported by [S2](S2.md)'s review on 2026-09-25 and recorded in TODO as not independently validated: a terminal's Ctrl-C signals the whole foreground process group, so the `xcodegen` that `run-mutants.py` runs to regenerate the copy after a restore died with it, the runner exited 2 with a generic tool error rather than "interrupted", and a mutated generated project could be left behind. By user decision on 2026-09-25 the finding also required that a post-restore regeneration failing for any reason stop the run, held by a verifier case that kills a `check=False` mutant of that call. The user assigned it on 2026-09-26, after [NB38](NB38.md) and before NB35.

**Boundary:** start the runner's short tools that run once its signal handlers are installed in their own session; leave `xcodebuild test` in the runner's process group; keep the post-restore regeneration checked. Deadlines (NB35), the lock's scope (S3), case selection (S4), handling SIGHUP or other unhandled signals, and any change to verdicts, exit codes, diagnostics, output protection, lock behavior, or restoration order were out of scope. Validation was verifier cases that signal the runner's process group from inside the stand-in tools, mutation evidence against the unmodified verifier, repeated runs for flakiness, real-Xcode runs including a process-group SIGINT during a real regeneration, AGENTS' gates, and the review skill's full procedure.

**Revalidation** at `3cec757`, with the verifier's fixture and the runner started as its own process group, as a terminal starts a job, and a stand-in tool signalling that whole group with SIGINT from inside the window: during the post-restore regeneration the run ended with exit 2 and `Command '[…xcodegen', 'generate']' died with <Signals.SIGINT: 2>.`, with the copy's `project.yml` restored and its generated file still mutated; with a generator that exits 0 on SIGINT, the runner printed `interrupted by signal 2; the copy was restored` over that mutated file; and a SIGINT during a mutant's pre-test generation, or during `uname -m`, ended with the same generic tool error rather than "interrupted". The real XcodeGen 2.46.0 finishes this project in about 30 ms; a SIGINT sent within its first 20 ms ended it by that signal (`-2`) without "Created project", once while it printed "Writing project...", and it kept running to completion when it had inherited SIGINT as ignored.

**Change.** `run_shielded` runs a short tool checked and captured with `start_new_session=True`, and the runner uses it for the pre-test `xcodegen generate`, `uname -m`, and the post-restore `xcodegen generate`. Outside the runner's process group a terminal's Ctrl-C reaches only the runner, whose existing handler records it; the tool finishes, and the runner stops once the copy is restored, with its existing "interrupted" diagnostic and exit 2. The post-restore regeneration stays checked, so any failure raises out of the restoring `finally`, and the run ends with exit 2, the tool's own message, no verdict for that mutant, and no later mutant; a comment there now says so. README states both.

**Sites.** Each launch site and what owns it:

- The pre-test and post-restore `xcodegen` calls and `uname -m` run after the handlers are installed, so a terminal's Ctrl-C used to kill them; each is shielded and held by its own case.
- `xcodebuild test` is deliberately not shielded. In the runner's group, a terminal's Ctrl-C ends it directly, as the runner's own `terminate` does for a signal sent to the runner alone, and a hangup, which the runner does not handle and which ends the runner at once, ends it too. In a session of its own it would outlive a runner ended by a hangup and keep testing into `--out` after the lock was released. `a_terminal_signal_still_reaches_the_test_tool` holds this.
- The `git` calls run before the handlers are installed, where either signal ends the runner by that signal before any mutant is applied, as README already says; a Ctrl-C there ends `git` either way, because `subprocess.run` kills its child when the runner's `KeyboardInterrupt` passes through it. They are unchanged.

**Verifier.** Five cases were added, and no existing case changed. `run_runner` gained two optional parameters: `own_session` starts the runner as its own process group, as a terminal starts a job, with a hangup's default action even if the verifier runs under `nohup`, so a stand-in can signal that group without reaching the verifier, and `env` adds variables. The stand-in generator sends the group a SIGINT when a mutant's `project.yml` carries `SPEC_CTRLC_BEFORE`, or while regenerating over `SPEC_CTRLC_AFTER` after the restore, and fails with a message while regenerating over `SPEC_REGEN_FAILS`; a stand-in `uname` placed first on `PATH` takes SIGINT's default action back, as a tool that handles Ctrl-C itself would, before signalling the group, so an inherited ignored SIGINT cannot pass for a shield; and the stand-in test tool signals the group with SIGINT (`GROUPINT`) or SIGHUP (`HANGUP`), recording whether it outlived a hangup, which a signal to the sender's own group rules out before `killpg` returns. The new cases are `a_terminal_interrupt_during_generation_before_a_test_run_lets_it_finish`, `a_terminal_interrupt_during_regeneration_after_a_restore_lets_it_finish`, `a_terminal_interrupt_during_the_architecture_query_is_an_interrupt`, `a_terminal_signal_still_reaches_the_test_tool`, and `a_failed_regeneration_after_a_restore_stops_the_run`. `./verify-mutation-runner.py` passes 99/99 on Python 3.13.9 and on `/usr/bin/python3` 3.9.6. `3cec757`'s runner fails exactly the three interrupt cases (96/99); the test-tool and regeneration-failure cases pass there, because they hold behavior the runner already had. The nine signal cases, old and new, passed 25 times on each interpreter with the verifier's first version and 30 times on each with its final one, some of those runs beside a real `xcodebuild`; the runner in those runs differed from the final one only in `run_shielded`'s docstring.

**Limitations.** A shielded tool no longer hears a terminal's signals at all: one that hangs is stopped by neither a Ctrl-C nor a hangup, and if the runner is ended by a signal it does not handle, such as SIGHUP, SIGQUIT, or SIGKILL, while a shielded tool runs, that tool finishes on its own after the runner has gone, possibly writing into the copy; XcodeGen takes about 30 ms here, and bounding a hang is NB35's. "The copy was restored" still verifies only the edit targets' bytes; the generated project is trusted to be restored because its regeneration completed, which the shield and the checked call now make true of a Ctrl-C. The verifier's process-group cases rely on `ps` and `/usr/bin/uname`, both standard on macOS. On the real runs only the one Ctrl-C during a test run checked that no test process outlived the runner, and the test host's exit was observed through process listings rather than asserted by a case, as S2 recorded.
