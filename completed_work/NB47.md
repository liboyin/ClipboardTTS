# NB47 — The build refuses an unrouted manager in tests

**Origin:** finding 2 of the main agent's read-only gap review of the [NB31](NB31.md)/[NB18](NB18.md) group on 2026-10-12, which the user asked on 2026-10-13 to act on. It was executed after [NB46](NB46.md), one task per commit.

After NB31, "no test builds an unrouted manager" held only by convention. `init(routing:)` accepts `nil` from any caller. `session` was an internal settable `var`, so with `@testable import` a test could build an unrouted manager or swap in another session. NB26's file-private token, which had confined the old unrouted path, was retired with that path.

**Boundary:**
- Make `TTSNetworkManager.session` read-only outside the type.
- Add a strict SwiftLint custom rule that applies to `Tests/` only. It rejects a direct manager construction anywhere but `Tests/TestNetworkSupport.swift`, and an `AppStartupDependencies.make` call that does not pass `productionSessionRouting:`.
- Keep the pure `TTSNetworkManager.sessionConfiguration(routing: nil)` legal.
- Update README.
- Production behaviour is unchanged; only access control, lint configuration and README change.
- Non-goals: a future unrouted `URLSession` path in `Sources` (gap-review finding 3); removing `make`'s default argument; NB46.

**Change:** `session` is `private(set)`. The new rule `test_routed_network_manager` has error severity, covers `Tests/` only, exempts the factory through its own `excluded` pattern, and skips comments, doc comments and strings. Its regex has four alternatives:

```
\bTTSNetworkManager\s*(\(|\.\s*init\b)|\.\s*init\s*\(\s*routing\s*:|\bAppStartupDependencies\s*\.\s*make\b(?!\s*\([^)]*\bproductionSessionRouting\s*:)|\bproductionSessionRouting\s*:\s*nil\b
```

- **Direct construction:** `TTSNetworkManager(` or an explicit `.init`.
- **Contextual initializer:** `.init(routing:`.
- **Missing routing label:** a `make` without `productionSessionRouting:` before its first `)`. Swift places that label before any closure argument, so the lookahead stops at the call's first `)`.
- **Nil routing:** `productionSessionRouting: nil`.

The contextual-initializer and nil-routing alternatives go beyond the boundary's literal list. The main agent accepted them, and the reviewer endorsed them, because each otherwise obtains an unrouted manager. README's factory paragraph names both guards, the compiler's and the regex's, and their limits.

**Validation:** macOS 26.7.1 arm64, Xcode 27.0 (27A266a), SwiftLint 0.65.1, XcodeGen 2.46.0. Every run used `xcodegen generate`, cleared the project's derived data, and built the strict unsigned Debug app with a fresh derived-data path.

- **Fresh baseline at `9cf747e`:** `./check-coverage.sh` exit 0, 396 tests, 0 failures. Managers 98.67%, application logic 97.82%. The Debug build succeeded.
- **Final candidate** (patch SHA-256 `fdfb6dd04409b929a64f47f374705915386953f4a6d3fe1ed44d1c19c4549469`): 396 tests, 0 failures, with coverage identical to the baseline overall and per file. The Debug build succeeded, and SwiftLint reported 0 violations in 110 files.
- The only source warning in both runs was N7's.

**Configuration evidence:** this was a build-policy change, so the evidence came from lint and compile probes rather than from XCTest mutants. The implementation agent ran them in a scratch copy made with `git archive HEAD` plus the candidate edits, linting the way the build does, with the root and nested configurations. Its evidence was produced on the frozen patch.

- **Forbidden spellings:** a probe of 15 forbidden spellings had each flagged once by the rule. It included single-line, multi-line, no-argument and trailing-closure `make` calls, explicit-init forms, the contextual initializer, and nil routing.
- **Allowed spellings:** a probe of allowed spellings and the current tree both produced 0 violations. The allowed probe covered every current `make` shape, `sessionConfiguration(routing: nil)`, and forbidden text inside comments, doc comments and strings.
- **Factory exclusion:** the factory file passes, and fails once at its construction when the exclusion is removed.
- **Revert:** with the rule deleted, the forbidden probe passes.
- **Regex parts:** each part is needed. An unbounded lookahead misses 4 forbidden calls, removing the lookahead flags 5 allowed calls, and dropping the match-kind exclusions flags 9 comment or string spans.
- **Read-only session:** a `@testable` test-file probe that assigns `manager.session` fails `build-for-testing` with "setter is inaccessible", and builds at HEAD.

The reviewer independently reproduced the 15 rejections and the clean allowed probe. It also showed three more things:

- Removing the contextual-initializer alternative loses one forbidden case, and removing the nil-routing alternative loses two.
- The same spellings under `Sources/` draw no diagnostic from the rule.
- An over-restriction to `private var session` fails the build at existing getter call sites.

**Limitations:** the rule is a regex, and these limits are documented in README and in the rule's YAML comment:

- A type alias, a spliced comment, or a nil routing passed through a variable or `AppStartupDependencies.productionSessionRouting` still gets past it.
- A `make` call whose earlier argument contains `)` is refused even when it names the routing, so the rule fails closed there; no current call does this.

Outside NB47 and not documented in README: a test can still build a bare, unrouted `URLSession` from `TTSNetworkManager.sessionConfiguration(routing: nil)`. That session is not a manager.
