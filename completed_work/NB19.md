# NB19 — One speech-session coordinator

Moved from [TODO.md](../TODO.md) on 2026-09-24 without rewording; the text below is the disposition as TODO recorded it, and its evidence is tied to the revisions it names.

**NB19 — Fixed.** `SpeechSessionCoordinator` is the one owner of a speech session, and the menu, Services, and Test Voice start and cancel through it rather than sequencing `AudioPlayerManager` and `TTSNetworkManager` themselves. It owns only what all three did identically: the refusal while the audio graph cannot play the selected format, the audio generation a session's PCM belongs to, and the binding of that request's audio and terminal event to it. The menu keeps its deferred clipboard read, idle revalidation, and OpenAI length refusal; Settings keeps its provider normalization, format validation, and credential handoff before the sample is spoken. Replacing a session takes two steps rather than three, because `startNewStream()` already discards the previous audio and `streamTTS` already revokes the previous request; cancelling in the owner as well advanced the request generation twice for one action, which the menu's deferred clipboard read reads as the number of requests a click started. A request now delivers exactly one terminal event, `SpeechStreamTermination.finished` or `.failed`, through the same delivery queue, callback authority, and generation check as its PCM, so it cannot overtake accepted audio and is withdrawn once a stop or replacement owns the pipeline; a request refused before it owns a task still terminates its session, and one whose automatic retry starts does not. `AudioPlayerManager.finishStream` applies it on the buffer queue behind that stream's own PCM and publishes `streamTermination`, which `stop()` clears. README owns the current contract. B2 consumed the terminal event this change published, and NB9 later paired a live format change with its request's cancellation through this owner: this change built the interface both need without changing what playback does.
