# S6 — Give provider defaults one owner

**Origin:** the full-project review of 2026-11-03 (TODO Evidence provenance) found the fresh-install model, voice, and endpoint defaults repeated in `SettingsView` and `RequestSettings.resolved`, catalog comments asking maintainers to update the copies, and the D28 migration taking its target from `openAIModels[0]`. On 2026-11-15 the user invoked grouped task execution for the Simplification proposals and chose S5, S6, and S9; S6 was committed second, after [S9](S9.md).

## Accepted boundary

The boundary was kept in the group's working review record.

- **Intent:** one small, pure owner holds the fresh-install defaults: the default provider, OpenAI's and Gemini's model and voice, Custom's empty model and voice, and Custom's native Kokoro endpoint (D34). Launch resolution, Settings' fallbacks, the D28 migration, `AppStartupDependencies.make`, and `TTSNetworkManager.init` read it. Migration targets the named default model, and each catalog keeps its default first.
- **Assumption (non-material):** "provider defaults" includes the default-provider fallback `"OpenAI"`, which was repeated three times. Identity strings (`SecretStore.swift`'s provider name, the sidebar's tags) are not defaults and stay.
- **Compatibility surface:** persistence keys, saved overrides, unknown saved values, provider normalization, Custom's empty model and voice and Kokoro endpoint, D28 migration (only `tts` models and `fable`/`nova`/`onyx` are rewritten), and catalog contents and order are all preserved. No value changes.
- **Non-goals:** OpenAI's and Gemini's fixed endpoints (repeated in `SettingsView.currentBaseURL`) are fixed endpoints, not defaults, and stay; the sample-rate default is unchanged; no generic provider framework.
- **Validation and done:** behavioral tests keep literal expectations and cover fresh startup, a hosted fresh form for every provider, and migration. Mutation evidence covers a drifted owner, a surface diverging from it, and migration regressions. The gates pass, and the change is reviewed and archived.

**Revalidation at `7d72ed0`:** the literals were repeated at `SettingsView.swift:9`–`:16` and `TTSNetworkManager+RequestSettings.swift:6`, `:8`, `:38`–`:47`, and `:71`, and the default provider at `ClipboardTTSApp.swift:68` and `TTSNetworkManager.swift:162`. No value mismatched.

## Implementation

**S6 — Done.** One implementation agent (a Claude Code general-purpose subagent) made the change; the main agent reviewed the diff and ran the final gates.

- `ProviderMetadataCatalog.swift` adds `enum ProviderDefaults`, documented as the one owner. Each model catalog is built from its named default (`[ProviderDefaults.openAIModel, "gpt-realtime-2.1"]`), so reordering a catalog cannot move a default, and `openAIModels` is now private. The comments asking maintainers to keep copies in sync are rewritten. The owner sits in this file rather than a new one: a file of constants alone has no executable lines, and `check-coverage.sh` refuses such a file unless it is listed in that script.
- `TTSNetworkManager+RequestSettings.swift` drops `nativeKokoroSpeechEndpoint` and `defaultOpenAIVoice`; `resolved` and the migration read `ProviderDefaults`, and the migration's conditions are unchanged.
- `SettingsView` drops its private `Fallback` enum; each `@AppStorage` fallback reads `ProviderDefaults`.
- `ClipboardTTSApp.swift` and `TTSNetworkManager.swift` fall back to `ProviderDefaults.provider.settingsValue`.
- New `Tests/ProviderDefaultsTests.swift`, with literal expectations throughout: `ProviderDefaultsSettingsTests.testAFreshFormShowsEachProvidersDefaultsAndOpensOnOpenAI` checks a hosted fresh form for every provider and that opening it stores no provider. `ProviderDefaultsStartupTests.testStartupWithNoStoredProviderSpeaksOpenAIAtTheProviderRate` stores only a 48-kHz Custom sample rate and checks that startup configures OpenAI's request inputs and a 24-kHz player. Before this change, nothing tested `AppStartupDependencies.make`'s default-provider fallback (mutant m09 below). The tests live in a new file because adding them to `SettingsViewTests.swift` or `AppStartupDependenciesTests.swift` would exceed the 400-line lint limit.
- `Tests/HostedSettings.swift` adds the Custom voice field.
- DESIGN's Source Layout and Network paragraph name the owner.
