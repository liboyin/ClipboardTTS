# T2 — Speak Copied Text does nothing visible when the clipboard holds no text

**Priority:** Non-blocking. Needs the user's decision on how the menu reports it.

- **Evidence:** Validated by source inspection at `01e94f3` on 2026-11-17. The deferred action in [MenuBarView](../../Sources/Views/MenuBarView.swift) returns silently when `getCopiedText()` gives no text.
- The click has already closed the menu by then. A clipboard that holds an image, a file or an empty string therefore looks like a click that the app ignored.
- **Related gap:** [TextExtractionManager](../../Sources/Managers/TextExtractionManager.swift) refuses only an empty string. Text of spaces and line breaks alone starts a provider request. The review did not verify what each provider answers.
- **Expected outcome:** The click tells the user that the clipboard holds no text to speak, and it starts no request. Text of whitespace alone counts as no text.
- **Decision needed:** An inline line under the button stays unseen until the user opens the menu again. The modal alert of the OpenAI length refusal interrupts the user, but the user sees it.
- **Validation:** A menu test injects a pasteboard reader without text. It asserts the report, one pasteboard read and an unchanged request generation. A superseded attempt still reports nothing.
- **Dependencies:** None. Services and the Test Voice action of Settings are outside this task.
