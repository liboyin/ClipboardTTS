# T5 — Stray whitespace around an endpoint, model, voice or key reaches the provider

**Priority:** Non-blocking.

- **Evidence:** Validated by a Foundation probe outside the repository, on macOS 27.2.1 on 2026-11-17. `URL(string:)` keeps a trailing space as `%20` in the path, and it refuses a leading space.
- A Custom endpoint with a trailing space therefore reaches a different path. One with a leading space reads "TTS configuration is invalid".
- A Gemini model with a trailing space puts `%20` before `:streamGenerateContent`. `URLRequest` drops a header value that holds a line break, so that request carries no key.
- **Not verified:** The review did not check whether a paste can put a line break into a Settings field. A trailing space needs no paste.
- **Source:** The request path trims nothing. Only the Custom check for an empty model and voice trims, in [the request builder](../../Sources/Managers/TTSNetworkManager+Requests.swift), and the request still sends the untrimmed values.
- **Expected outcome:** A request uses the endpoint, model, voice and key without surrounding spaces and line breaks. The stored values and the displayed values stay as typed. Inner spaces stay.
- **Assumption:** No provider gives meaning to whitespace around these four values.
- **Validation:** Tests of the built request for each value and each provider. Mutation evidence covers a revert and a trim that also removes inner spaces.
- **Dependencies:** None. T6 (Gemini endpoint) changes the same endpoint builder, so do T6 first.
