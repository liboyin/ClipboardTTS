# NB54 — Give menu controls explicit accessible purposes and values

**Priority:** Non-blocking.

**Non-blocking; source gap Validated, runtime announcements unverified — 2026-11-03 review.** `Sources/Views/MenuBarView.swift:89` and `:99` constructed position and speed sliders without labels or explicit units (since [B5](../closed/B5.md), `MenuSlider` at `:90` and `:101`, an `NSSlider` given no accessibility label); the adjacent Speed text is a separate view. Settings and Quit at `:43`–`:56` use only symbol images without action-specific accessible names. Useful announcements currently depend on framework inference. **Outcome:** sliders identify playback position and rate with meaningful time/multiplier values, and icon actions identify their purpose, preserving the visual layout and playback/click contracts. **Validation:** first inspect the menu with VoiceOver, then verify distinguishable names, values, enabled states, and keyboard operation after the change; retain existing behavioral coverage. The current windowless menu tests cannot establish the live accessibility result, so record that manual check explicitly rather than treating source modifiers as proof. **Dependencies:** none; any replacement of controls rather than adding semantics needs its own boundary. **Disposition:** backlogged at the user's request; not a claim of an observed VoiceOver failure.
