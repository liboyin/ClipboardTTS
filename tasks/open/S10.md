# S10 — Review how much code verifies the tooling

**Priority:** Non-blocking proposal. Needs the user's decision, and is not approved for implementation.

**Non-blocking simplification proposal; sizes Validated, benefit a design judgment — 2026-11-03 second review.** `verify-mutation-runner.py` (2,913 lines) and `verify-coverage-gate.py` (662 lines) verify `run-mutants.py` (688 lines) and `check-coverage.sh` (324 lines): about 3,600 lines of Python guarding about 1,000 lines of tooling, close to the 4,500 lines of application Swift. Every case traces to an accepted task (S2–S4, NB33–NB45, NB15–NB16), so none is known to be redundant. **Proposed outcome:** the user inventories which decision or failure each verifier case protects, consolidates cases that protect the same property (table-driven where they are not already), and retires any whose scenario they no longer want supported, such as unusual locales or signals. If it shortens both files, the coverage policy could move out of `check-coverage.sh`'s heredoc into a Python file the verifier imports. **Compatibility/validation:** no gate weakens without an explicit superseding decision, D23 and the exit-code contracts are preserved, and each retired case names the retained case that kills the same mutant, as AGENTS requires. **Dependencies:** needs a user decision on how much tooling robustness to keep. **Disposition:** proposal recorded, not approved for implementation.
