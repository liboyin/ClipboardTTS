# NB56 — Production initializers default to the developer's Keychain

**Outcome:** Fixed (D39): `TTSNetworkManager` and `SettingsView` take no default secret store, so an omitted one fails to build, and the strict `keychain_secret_store` lint rule refuses naming `KeychainSecretStore` anywhere but its declaration and the composition root.

**Origin:** the second full-project review of 2026-11-03 at `23a8871` (TODO's evidence provenance). `TTSNetworkManager.init` and `SettingsView.init` defaulted `secretStore` to `KeychainSecretStore()`. Production never used either default, but nothing stopped a test or hosted form that omitted the argument from reaching the developer's Keychain, which AGENTS forbids.

**Decision:** D39 (2026-11-16). NB56 left the guard to the user: a strict lint rule, or a recorded reason to accept the surviving mutant. The user chose the lint rule.

## Implementation

**NB56 — Fixed (D39).** The main agent made the change directly.

- Both initializers' `secretStore` parameters lost their default, so an omitted store fails to compile; each initializer's doc comment says so.
- `.swiftlint.yml` gains the strict custom rule `keychain_secret_store`, over `Sources/` and `Tests/`. Its regex is `(?<!\bclass\s{1,20})\bKeychainSecretStore\b`, excluding comments, doc comments and strings. It refuses the type name anywhere except its own `class` declaration, so `AppStartupDependencies.make`'s `productionSecretStore:` default carries the one line-scoped disable.
- `ClipboardTTSApp.swift`'s composition-root comment names the Keychain alongside the defaults domain. DESIGN's settings-storage guards name the compiler's and the rule's share.

**Assumption (non-material):** the rule refuses the bare name rather than only spellings of construction. Evidence: nothing else in `Sources/` or `Tests/` named the type, and the bare-name regex is simpler and also refuses a type alias. Effect: a future reference needs a line-scoped disable with its reason.

**Compatibility:** no runtime behavior changed. Production already passed the startup store to both initializers, and every test passed an owned store.

## Accepted boundary

### Compact entry, removed from TODO by this commit

**Non-blocking; Validated — source inspection, 2026-11-03 second review.** `TTSNetworkManager.init` (`Sources/Managers/TTSNetworkManager.swift:150`) and `SettingsView.init` (`Sources/Views/SettingsView.swift:50`) default `secretStore` to `KeychainSecretStore()`. Production never uses either default, because `AppStartupDependencies.make` and `ClipboardTTSApp` pass the startup store explicitly. Every test passes a store today (`TestNetworkFactory`, `HostedSettings`), but nothing enforces that: no lint rule covers `KeychainSecretStore`, so a test or hosted form that omits the argument would read, write, or delete the developer's Keychain, which AGENTS forbids. DESIGN's test harness already relies on the compiler for the matching preference rule, since no settings API in `Sources` defaults to `.standard`. **Outcome:** remove both defaults so that an omitted store fails to build, leaving `AppStartupDependencies.make` as the only place that names the Keychain. **Validation:** app and test builds pass, and the composition root is the only `KeychainSecretStore(` construction in `Sources`. Reinstating a default survives every test, so either add a strict lint rule refusing that construction outside the composition root, which kills the mutant, or record why the mutant is accepted; the user chooses. **Dependencies:** none.

By the execution revision `9546bec` the two defaults had moved to `TTSNetworkManager.swift:129` and `SettingsView.swift:35`.

### Execution boundary (D39)

**Intent:** an omitted secret store fails to build, and the only place in `Sources/` or `Tests/` that names `KeychainSecretStore` outside its declaration is `AppStartupDependencies.make`.

**Direction:** remove both defaults and document that the store has no default. Add the strict `keychain_secret_store` rule with one disable at the composition root. Name the guard in DESIGN.

**Compatibility surface:** Settings, Keychain persistence, menu, Services, clipboard, provider-request and audio-session contracts are preserved; no runtime behavior changes.

**Non-goals:** `AppStartupDependencies.make`'s own `productionSecretStore` default stays, since it is the composition root. `KeychainSecretStore` itself, the coverage exclusions, and other stores' defaults are unchanged. No runtime test of the Keychain is added.

**Validation and done:** baseline and final gates pass; lint and end-to-end mutation evidence covers revert, regression and over-restriction; the review has no Blocking finding; this record is written and the TODO entry removed.
