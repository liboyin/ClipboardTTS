# NB54 — Give menu controls explicit accessible purposes and values

**Outcome:** Fixed. The menu's sliders state a name and a spoken value, and its three icon buttons state their action.

**Non-blocking; source gap Validated, runtime announcements unverified — 2026-11-03 review.** `Sources/Views/MenuBarView.swift:89` and `:99` constructed position and speed sliders without labels or explicit units (since [B5](../closed/B5.md), `MenuSlider` at `:90` and `:101`, an `NSSlider` given no accessibility label); the adjacent Speed text is a separate view. Settings and Quit at `:43`–`:56` use only symbol images without action-specific accessible names. Useful announcements currently depend on framework inference. **Outcome:** sliders identify playback position and rate with meaningful time/multiplier values, and icon actions identify their purpose, preserving the visual layout and playback/click contracts. **Validation:** first inspect the menu with VoiceOver, then verify distinguishable names, values, enabled states, and keyboard operation after the change; retain existing behavioral coverage. The current windowless menu tests cannot establish the live accessibility result, so record that manual check explicitly rather than treating source modifiers as proof. **Dependencies:** none; any replacement of controls rather than adding semantics needs its own boundary. **Disposition:** backlogged at the user's request; not a claim of an observed VoiceOver failure.

## Origin and boundary

The task comes from the 2026-11-03 review. The user accepted it for implementation on 2026-11-17, together with [NB60](NB60.md). The two tasks share one candidate, one review and one manual session.

- **Intent:** VoiceOver states what each menu control is. The two sliders give a name and a spoken value. The Settings, Quit and play or pause buttons give their action.
- **Dependencies:** D36, which made the sliders AppKit controls. No other task.
- **Implementation direction:**
  - `MenuSlider` takes a required accessibility label and a formatter for its spoken value.
  - `DragDeferringSlider` answers its accessibility value description from its current value, through that formatter.
  - `MenuBarView` names the sliders "Playback position" and "Playback speed". A new file, `Sources/Views/MenuSpokenValues.swift`, holds the pure formatting functions.
  - The three icon buttons gain `.accessibilityLabel`.
- **Decisions within DESIGN's latitude (assumptions):**
  - The play or pause button counts as an icon action. It shows only a symbol, like Settings and Quit. The effect is one more label.
  - The wording is English, like every other string of the app.
  - The spoken duration comes from the app's own formatter, not from `DateComponentsFormatter`. The text then does not follow the locale of the host, which the tests run on.
- **Compatibility surface:** the menu only.
  - Preserved: the layout, each slider's range, step and enabled state, the values that an edit delivers, and the deferral of published values during a drag.
  - Preserved: what a click of each button does.
  - Not touched: Settings (NB60 owns it), Services, the clipboard, persistence, provider requests and audio sessions.
- **Non-goals:** a replacement of the SwiftUI buttons by AppKit controls, tooltips, localisation, and the seek cost that [NB55](NB55.md) measured.
- **Validation:**
  - Hosted windowless tests assert the label and the spoken value of each slider, also after its value changes. Unit tests cover the formatting functions.
  - The existing slider and menu tests stay as they are.
  - A windowless host shows no SwiftUI button to AppKit, as [B5](B5.md) records. No test can therefore observe the three button labels. The user's VoiceOver session verifies them.
- **Mutation evidence:**
  - The slider label and the spoken value: a revert, a plausible regression (swapped labels, a stale value, a wrong unit) and an over-restriction.
  - The three button labels: not applicable. No test can observe them, so a mutant cannot fail one. The manual check stands in.
- **Done:** both gates, the mutation evidence, the review, the closed records, and the user's VoiceOver session recorded as a manual check.

## Implementation

The main agent made the change directly, on `fec6589`. The grouped task skill prescribes implementation agents. The session's instructions did not allow subagents, and the change was small.

- `MenuSlider` takes a required `accessibilityLabel` and a `spokenValue` formatter. It sets the label on every update.
- `DragDeferringSlider` overrides `accessibilityValueDescription()`. It formats the position the thumb is at now, so the text cannot lag behind a drag.
- A stepped slider describes the step that it would deliver, not the raw position.
- `Sources/Views/MenuSpokenValues.swift` is new. It holds three pure functions: a duration in hours, minutes and seconds, a position within a duration, and a speed to one decimal.
- `MenuBarView` names the sliders "Playback position" and "Playback speed". The buttons are labelled "Settings", "Quit Clipboard TTS", and "Play" or "Pause".
- DESIGN gains the new file in its source layout, and one rule on accessible names.
