# NB60 — Settings' suggestion pickers have no accessible name

**Outcome:** Fixed. Each suggestion picker and each model or voice field in Settings states which of the two it sets.

**Non-blocking; source gap Validated, runtime announcements unverified — 2026-11-03 second review.** `Sources/Views/ModelVoiceConfigurationView.swift:45` and `:58` build the model and voice pickers as `SuggestionPicker` pop-up buttons (since [B5](../closed/B5.md); before it, `Picker("")` with `.labelsHidden()`) in a 30-point frame, with no accessibility label, beside text fields labelled only by their placeholders, so VoiceOver can reach two unnamed pop-up buttons. NB54 covers only the menu. **Outcome:** each picker and field says whether it chooses the model or the voice, preserving the layout and the exactly-once edit contract. **Validation:** as for NB54: inspect with VoiceOver first, record the manual result, and keep the existing picker coverage. **Dependencies:** none; may share a boundary and a manual session with NB54. [S5](../closed/S5.md) has landed, and the line numbers above are from after it.

## Origin and boundary

The task comes from the second review of 2026-11-03. The user accepted it for implementation on 2026-11-17, together with NB54 (menu accessibility). [NB54's boundary](NB54.md#origin-and-boundary) states what the two tasks share: the candidate, the review and the manual session.

- **Intent:** in Settings, each suggestion picker and each text field says whether it sets the model or the voice.
- **Dependencies:** D36, which made the pickers AppKit pop-up buttons, and D38, which gives each form its own catalogs.
- **Implementation direction:**
  - `SuggestionPicker` takes a required accessibility label, and sets it on its `NSPopUpButton`.
  - `ModelVoiceConfigurationView` names the pickers "Model suggestions" and "Voice suggestions".
  - The two text fields gain `.accessibilityLabel` with "Model" and "Voice".
- **Decisions within DESIGN's latitude (assumptions):** the wording is English, like every other string of the app.
- **Compatibility surface:** Settings only.
  - Preserved: the 30-point slot of each picker, the choices and the selection that it shows, and one callback for each edit.
  - Not touched: the menu (NB54 owns it), persistence and provider requests.
- **Non-goals:** names for the other Settings fields, and a visible label beside the pickers.
- **Validation:**
  - Hosted windowless tests assert the label of each picker, in the picker's own tests and in the hosted form.
  - The existing picker and Settings tests stay as they are.
  - The user's VoiceOver session verifies the announcements of the pickers and the text fields.
- **Mutation evidence:** the picker label: a revert and a plausible regression (swapped labels). An over-restriction does not apply, because the label has no condition.
- **Done:** as for NB54.

## Implementation

The main agent made the change directly, on `fec6589`, in one candidate with NB54.

- `SuggestionPicker` takes a required `accessibilityLabel`. It sets the label on its `NSPopUpButton` on every update.
- `ModelVoiceConfigurationView` names the pickers "Model suggestions" and "Voice suggestions". The two text fields are labelled "Model" and "Voice".

- The form's other fields have no explicit name. The task did not cover them.
