# NB61 — Test Voice's stopped-graph test refuses an endpoint OpenAI no longer uses

**Outcome:** Fixed: Test Voice's stopped-graph test fails on any request it starts, HTTP or Realtime, checking synchronously that no Realtime connection opened instead of refusing a retired URL.

**Origin:** the 2026-11-03 gap review of NB57, N11, and N12. `testTestVoiceDoesNotStartRequestWhenDefaultRateEngineCannotRecover` (`Tests/SettingsViewTests.swift`) selected OpenAI and failed only a request to `https://api.openai.com/v1/audio/speech`. Since D26, OpenAI speech connects to `wss://api.openai.com/v1/realtime`; that HTTPS address was Custom's fallback until [N13](N13.md). Its comment also said opening Settings fetches suggestions, which D31 removed. The URL assertion therefore could not fail. Whether the remaining assertions (`isStreaming`, `sampleRate`, `sampleRateError`) still failed when Test Voice ignored a stopped graph had not been checked.

- **Intent:** the test fails whenever Test Voice starts any speech request, HTTP or Realtime, and its comment states the current premise (opening Settings sends no request, D31).
- **Compatibility surface and non-goals:** tests only. No production, menu, Settings, Services, clipboard, persistence, provider-request, or audio-session contract changes, and no other test.

The same mutant runs against the original test at `057b50f`, and this record states whether that also failed. For over-restriction, Test Voice with a working graph still starts a request.
- **Done:** gates pass, mutants are killed by the named test, and NB61 is archived.

**Revalidation at `057b50f`:** the cited lines were present, off by one. Without scripted connections, a Realtime request opens a WebSocket task on the mock-routed session, which `MockURLProtocol` claims, so a handler that refused every request would see it. DESIGN's hosted-Settings guidance confirms that opening Settings sends no request.

## Implementation

**NB61 — Fixed.** The main agent made this test-only change directly; it judged the one-test edit too small to be worth an implementation agent. The test now:

- builds its manager with `ScriptedRealtimeConnections`, and asserts right after the click that none was opened. The manager calls the connection factory inside `streamTTS`, which the click runs, so the check is synchronous;
- installs a handler that fails on any HTTP request, naming its URL;
- cancels and drains any scripted connection in a teardown block;
- replaces the comment with the current premise.

The `sampleRate`, `sampleRateError`, and `isStreaming` assertions are kept. The file stays at 399 lines, under strict SwiftLint's 400-line `file_length` limit.

An intermediate revision used an unscripted connection and relied on the handler alone. Mutation showed the handler did see the `wss://` request. The same run also showed that the kept `isStreaming` assertion passed under the mutant there, while at `057b50f` it failed, so its outcome depends on timing. The handler runs asynchronously, and teardown's session invalidation could in principle cancel the task before it loads. The synchronous connection check replaced that reliance.
